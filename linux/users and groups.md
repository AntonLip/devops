
Пользователи и группы (20 минут)

### Типы пользователей

**1. Root (суперпользователь):**
- UID = 0
- Полный доступ ко всей системе
- Может делать все
- Опасен для обычной работы

**2. Системные пользователи:**
- UID < 1000 (обычно)
- Для работы системных сервисов
- Примеры: `daemon`, `www-data`, `mysql`
- Без возможности входа в систему (shell = `/usr/sbin/nologin`)

**3. Обычные пользователи:**
- UID >= 1000
- Ограниченные права
- Домашняя директория
- Могут использовать sudo

**4. Пользователи с sudo:**
- Обычные пользователи с правами sudo
- Могут выполнять команды от root
- Настраивается через `/etc/sudoers`

### Управление пользователями и группами

**Группы:**

**Типы групп:**
- **Основная группа (Primary Group)** — группа по умолчанию для пользователя
- **Дополнительные группы (Secondary Groups)** — дополнительные группы пользователя

**Системные группы:**
- GID < 1000
- Для системных сервисов
- Примеры: `adm`, `sudo`, `www-data`

**Обычные группы:**
- GID >= 1000
- Для пользователей

**Управление группами:**

**Создание группы:**
```bash
# Интерактивно
sudo addgroup groupname

# Неинтерактивно
sudo groupadd groupname
sudo groupadd -g 1001 groupname  # с указанием GID
```

**Удаление группы:**
```bash
sudo groupdel groupname
```

**Изменение группы:**
```bash
# Изменить GID
sudo groupmod -g 2000 groupname

# Изменить имя
sudo groupmod -n newname oldname
```

**Управление пользователями в группах:**
```bash
# Добавить пользователя в группу
sudo usermod -aG groupname username

# Изменить основную группу
sudo usermod -g groupname username

# Удалить пользователя из группы
sudo gpasswd -d username groupname
```

**Просмотр групп:**
```bash
# Группы текущего пользователя
groups
id

# Группы другого пользователя
groups username
id username

# Все группы
cat /etc/group
getent group

# Пользователи в группе
getent group groupname
```

**Структура /etc/group:**
```
groupname:x:GID:users
```
- `groupname` — имя группы
- `x` — пароль (в /etc/gshadow)
- `GID` — Group ID
- `users` — список пользователей (через запятую)

### Система прав доступа

**Права доступа** — механизм контроля, кто и что может делать с файлами и директориями.

**Три типа прав:**
- **r (read, чтение)** — значение 4
  - Для файлов: чтение содержимого
  - Для директорий: просмотр списка файлов (ls)
- **w (write, запись)** — значение 2
  - Для файлов: изменение содержимого
  - Для директорий: создание/удаление файлов
- **x (execute, выполнение)** — значение 1
  - Для файлов: выполнение как программы
  - Для директорий: вход в директорию (cd)

**Три категории пользователей:**
- **Owner (владелец)** — пользователь, создавший файл или назначенный владельцем
- **Group (группа)** — группа владельца файла
- **Others (остальные)** — все остальные пользователи системы

**Представление прав:**
```
rwx rwx rwx
│││  │││  │││
│││  │││  └─ others (остальные)
│││  └└└──── group (группа)
└└└───────── owner (владелец)
```

**Пример:**
```
-rwxr-xr-- 1 user developers 1024 file.txt
│││││││││
││││││││└─ others: r-- (чтение)
│││││││└── group: r-x (чтение и выполнение)
││││││└─── owner: rwx (все права)
```

### 3.4. Изменение прав доступа

**Цифровой способ (octal notation):**

Система основана на сумме значений:
- 4 = read (r)
- 2 = write (w)
- 1 = execute (x)
- 0 = нет прав

Комбинации:
- 7 = 4+2+1 = rwx (все права)
- 6 = 4+2 = rw- (чтение и запись)
- 5 = 4+1 = r-x (чтение и выполнение)
- 4 = 4 = r-- (только чтение)
- 0 = --- (нет прав)

**Примеры:**
```bash
# Полные права для всех
chmod 777 file.txt
# rwxrwxrwx

# Владелец: все права, остальные: чтение
chmod 744 file.txt
# rwxr--r--

# Владелец: чтение и запись, группа и остальные: только чтение
chmod 644 file.txt
# rw-r--r--

# Только владелец имеет доступ
chmod 600 file.txt
# rw-------

# Владелец и группа: чтение и запись, остальные: нет доступа
chmod 660 file.txt
# rw-rw----

# Владелец: все права, группа: чтение и выполнение, остальные: выполнение
chmod 751 file.txt
# rwxr-x--x
```

**Символьный способ:**

Формат: `[ugoa][+-=][rwx]`

Категории:
- `u` — user (владелец)
- `g` — group (группа)
- `o` — others (остальные)
- `a` — all (все)

Операции:
- `+` — добавить право
- `-` — убрать право
- `=` — установить точно

**Примеры:**
```bash
# Добавить выполнение для владельца
chmod u+x file.txt

# Убрать запись для группы
chmod g-w file.txt

# Добавить чтение для остальных
chmod o+r file.txt

# Добавить выполнение для всех
chmod a+x file.txt

# Установить точно: владелец rwx, группа rx, остальные r
chmod u=rwx,g=rx,o=r file.txt

# Комбинирование
chmod u+x,g+w file.txt  # добавить выполнение владельцу и запись группе
```

### Права для директорий

**Важно:** Права для директорий имеют другой смысл!

**r (read) для директории:**
- Позволяет просматривать список файлов (ls)
- Без r нельзя увидеть содержимое директории

**w (write) для директории:**
- Позволяет создавать и удалять файлы в директории
- НЕ позволяет редактировать файлы напрямую
- Нужно w на директорию, чтобы удалить файл, даже если у файла есть w

**x (execute) для директории:**
- Позволяет войти в директорию (cd)
- Позволяет получить доступ к файлам внутри
- Без x нельзя получить доступ к файлам, даже если есть r

**Типичные комбинации для директорий:**
```bash
# 755 - стандартные права для директорий
chmod 755 directory/
# rwxr-xr-x
# Владелец: все, группа и остальные: чтение и вход

# 775 - для совместной работы
chmod 775 directory/
# rwxrwxr-x
# Владелец и группа: все права, остальные: чтение и вход

# 700 - приватная директория
chmod 700 directory/
# rwx------
# Только владелец имеет доступ

# 750 - доступ для группы
chmod 750 directory/
# rwxr-x---
# Владелец: все, группа: чтение и вход, остальные: нет доступа
```

**Практический пример:**
```bash
# Создать директорию
mkdir testdir

# Установить права 755
chmod 755 testdir

# Попытка доступа без x
chmod -x testdir
cd testdir  # Permission denied!

# Попытка доступа без r
chmod +x testdir
chmod -r testdir
ls testdir  # Permission denied!
```

### Специальные права доступа

**SUID (Set User ID):**

**Для файлов:**
- Файл выполняется с правами владельца, а не пользователя
- Используется для программ, которым нужны повышенные права

**Примеры:**
```bash
# /usr/bin/passwd имеет SUID
ls -l /usr/bin/passwd
# Вывод: -rwsr-xr-x ... root ... /usr/bin/passwd
#        ^
#        s вместо x = SUID

# passwd может изменять /etc/shadow (требует root прав)
# Но обычный пользователь может запустить passwd
# И программа выполнится с правами root
```

**Установка SUID:**
```bash
# Символьный способ
chmod u+s file
chmod 4755 file  # 4 = SUID бит

# Проверка
ls -l file
# Вывод: -rwsr-xr-x ... (s вместо x у владельца)
```

**Опасность SUID:**
- Если файл с SUID принадлежит root, выполняется от root
- Уязвимость в таком файле может дать root доступ
- Использовать осторожно!

**SGID (Set Group ID):**

**Для файлов:**
- Файл выполняется с правами группы владельца
- Используется реже, чем SUID

**Для директорий (более важно):**
- Новые файлы в директории создаются с группой директории
- А не с основной группой пользователя
- Критично для совместной работы!

**Пример работы SGID:**
```bash
# Создать группу
sudo groupadd developers

# Создать директорию с SGID
sudo mkdir /shared
sudo chgrp developers /shared
sudo chmod 2775 /shared  # 2 = SGID бит

# Проверка
ls -ld /shared
# Вывод: drwxrwsr-x ... developers ... (s вместо x у группы)

# Пользователь dev1 создает файл
touch /shared/file.txt
ls -l /shared/file.txt
# Вывод: -rw-r--r-- dev1 developers file.txt
#        ^^^^^^^^^^
#        Группа = developers (благодаря SGID), а не основная группа dev1!
```

**Установка SGID:**
```bash
# Для директории
chmod g+s directory/
chmod 2755 directory/  # 2 = SGID бит

# Проверка
ls -ld directory/
# Вывод: drwxr-sr-x ... (s вместо x у группы)
```

**Sticky Bit:**

**Только для директорий:**
- Пользователи могут удалять только свои файлы
- Даже если у них есть права на запись в директорию
- Классический пример: `/tmp`

**Пример:**
```bash
# /tmp имеет sticky bit
ls -ld /tmp
# Вывод: drwxrwxrwt ... (t вместо x у остальных)

# Пользователь user1 создает файл
touch /tmp/user1_file.txt

# Пользователь user2 НЕ может удалить файл user1
# Даже если /tmp доступен для записи всем
rm /tmp/user1_file.txt  # Operation not permitted
```

**Установка Sticky Bit:**
```bash
chmod +t directory/
chmod 1755 directory/  # 1 = Sticky bit

# Проверка
ls -ld directory/
# Вывод: drwxr-xr-t ... (t вместо x у остальных)
```

**Комбинирование специальных прав:**
```bash
# SUID + SGID
chmod 6755 file  # 6 = 4 (SUID) + 2 (SGID)

# SGID + Sticky Bit (для директории)
chmod 3755 directory/  # 3 = 2 (SGID) + 1 (Sticky)

# Все три (для директории)
chmod 7755 directory/  # 7 = 4 + 2 + 1
```

### Изменение владельца и группы

**chown (change owner):**

```bash
# Изменить владельца и группу
sudo chown user:group file.txt

# Изменить только владельца
sudo chown user file.txt

# Изменить только группу
sudo chown :group file.txt

# Рекурсивно (для директории и всего содержимого)
sudo chown -R user:group directory/

# Сохранить символические ссылки (не следовать им)
sudo chown -h user:group symlink
```

**chgrp (change group):**

```bash
# Изменить группу
sudo chgrp group file.txt

# Рекурсивно
sudo chgrp -R group directory/
```

**Практические примеры:**
```bash
# Веб-сервер: файлы принадлежат www-data
sudo chown -R www-data:www-data /var/www/html

# Общая директория: группа developers
sudo chgrp -R developers /opt/project
sudo chmod -R g+w /opt/project  # группа может писать

# Приватные файлы: только владелец
chmod 600 ~/.ssh/id_rsa
chown $USER:$USER ~/.ssh/id_rsa
```

### ACL (Access Control Lists)

**ACL** — расширенная система прав доступа, позволяющая задавать права для конкретных пользователей и групп сверх стандартных прав.

**Установка ACL:**
```bash
# Установить ACL для пользователя
sudo setfacl -m u:username:rwx file.txt

# Установить ACL для группы
sudo setfacl -m g:groupname:r-x file.txt

# Установить ACL для остальных
sudo setfacl -m o::r-- file.txt

# Комбинирование
sudo setfacl -m u:user1:rwx,g:developers:r-x file.txt

# Рекурсивно для директории
sudo setfacl -R -m u:username:rwx directory/
```

**Просмотр ACL:**
```bash
# Просмотр ACL файла
getfacl file.txt

# Вывод будет примерно таким:
# # file: file.txt
# # owner: user
# # group: developers
# user::rw-
# user:user1:rwx
# group::r--
# group:developers:r-x
# mask::rwx
# other::r--
```

**Удаление ACL:**
```bash
# Удалить ACL для конкретного пользователя
sudo setfacl -x u:username file.txt

# Удалить ACL для группы
sudo setfacl -x g:groupname file.txt

# Удалить все ACL
sudo setfacl -b file.txt

# Рекурсивно удалить все ACL
sudo setfacl -R -b directory/
```

**Маска ACL (mask):**
```bash
# Установить маску (максимальные эффективные права)
sudo setfacl -m m::rwx file.txt

# Маска ограничивает максимальные права, которые могут быть установлены
```

**Практический пример ACL:**
```bash
# Файл с базовыми правами
chmod 644 file.txt  # rw-r--r--

# Добавить права для конкретного пользователя
sudo setfacl -m u:user1:rwx file.txt

# Теперь user1 имеет полные права, хотя файл имеет только 644
# Остальные пользователи имеют только чтение
```

### Типичные комбинации прав

**Безопасные конфигурации:**

```bash
# Приватные файлы (только владелец)
chmod 600 file.txt
# Использование: пароли, ключи SSH, конфигурации

# Приватные директории
chmod 700 directory/
# Использование: домашние директории, приватные данные

# Чтение для всех, запись только владельцу
chmod 644 file.txt
# Использование: конфигурационные файлы, документация

# Стандартные права для директорий
chmod 755 directory/
# Использование: публичные директории, веб-контент

# Совместная работа в группе
chmod 775 directory/
chmod g+s directory/  # SGID для наследования группы
# Использование: проектные директории, общие файлы

# Исполняемые файлы
chmod 755 script.sh
# Использование: скрипты, программы

# Веб-сервер
chmod 644 /var/www/html/*.html
chmod 755 /var/www/html/
# Использование: статические файлы веб-сайта
```

### Проверка и диагностика прав

**Просмотр прав:**
```bash
# Детальная информация
ls -l file.txt
ls -ld directory/

# Статистика файла
stat file.txt
# Показывает: права, владельца, размер, даты и т.д.

# Права в числовом формате
stat -c "%a %n" file.txt
# Вывод: 644 file.txt

# Права в символьном формате
stat -c "%A %n" file.txt
# Вывод: -rw-r--r-- file.txt
```

**Поиск файлов по правам:**
```bash
# Файлы с определенными правами
find . -perm 644
find . -perm -644  # все указанные права должны быть
find . -perm /644  # хотя бы одно из прав

# Файлы с SUID
find /usr -perm -4000 2>/dev/null

# Файлы с SGID
find /usr -perm -2000 2>/dev/null

# Директории с Sticky Bit
find / -type d -perm -1000 2>/dev/null

# Опасные права (доступны для записи всем)
find . -perm -002  # world-writable
find . -perm -022  # group и world writable
```

**Проверка доступа:**
```bash
# Проверить, может ли пользователь читать файл
sudo -u username test -r file.txt && echo "Может читать"

# Проверить, может ли пользователь писать
sudo -u username test -w file.txt && echo "Может писать"

# Проверить, может ли пользователь выполнять
sudo -u username test -x file.txt && echo "Может выполнять"
```

### Best Practices для прав доступа

**Принципы безопасности:**

1. **Принцип наименьших привилегий:**
   - Давать минимально необходимые права
   - Избегать 777 (все права для всех)

2. **Использование групп:**
   - Управлять правами через группы
   - Использовать SGID для совместной работы

3. **Регулярная проверка:**
   - Проверять файлы с SUID/SGID
   - Искать файлы с опасными правами

4. **Документирование:**
   - Записывать, почему установлены определенные права
   - Особенно для нестандартных конфигураций

5. **Тестирование:**
   - Проверять права перед применением на продакшене
   - Тестировать доступ от разных пользователей

**Типичные ошибки:**

```bash
# ❌ ПЛОХО: Все права для всех
chmod 777 file.txt

# ✅ ХОРОШО: Только необходимые права
chmod 644 file.txt  # или 755 для директорий

# ❌ ПЛОХО: SUID на скриптах (опасно)
chmod 4755 script.sh

# ✅ ХОРОШО: Использовать sudo вместо SUID
# Настроить sudo для конкретных команд

# ❌ ПЛОХО: Не использовать SGID для общих директорий
chmod 775 /shared  # без SGID

# ✅ ХОРОШО: SGID для автоматического наследования группы
chmod 2775 /shared  # с SGID
```
