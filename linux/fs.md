## Файловая система

### Способы обмена информацией

**Между процессами:**
- **Файлы** - через файловую систему
- **Pipes (каналы)** - однонаправленная передача данных
- **Named Pipes (FIFO)** - именованные каналы
- **Sockets (сокеты)** - двусторонняя связь
- **Shared Memory** - разделяемая память
- **Message Queues** - очереди сообщений

**Между системами:**
- **NFS (Network File System)** - сетевая файловая система
- **SMB/CIFS** - протокол для Windows
- **FTP/SFTP** - передача файлов
- **SCP** - безопасное копирование через SSH
- **rsync** - синхронизация файлов

#### Основные разновидности ФС Linux

**Файловая система** - способ организации и хранения данных на диске.

**Типы файловых систем:**

**1. ext2 (Second Extended File System):**
- Старая файловая система
- Без журналирования
- Используется для загрузочных разделов

**2. ext3 (Third Extended File System):**
- Добавлено журналирование
- Обратная совместимость с ext2
- Надежная и стабильная

**3. ext4 (Fourth Extended File System):**
- Современная стандартная ФС Linux
- Улучшенная производительность
- Поддержка больших файлов и разделов
- Журналирование
- Используется по умолчанию в большинстве дистрибутивов

**4. XFS:**
- Высокая производительность
- Хорошо для больших файлов
- Используется в RHEL по умолчанию
- Хорошая масштабируемость

**5. Btrfs (B-tree File System):**
- Современная файловая система
- Поддержка снимков (snapshots)
- Сжатие данных
- RAID-подобные функции
- Copy-on-write

**6. ZFS:**
- Продвинутая файловая система
- Отличная для больших объемов данных
- Встроенная защита от ошибок
- Сжатие и дедупликация

**7. FAT32:**
- Совместимость с Windows
- Ограничение размера файла 4GB
- Используется для USB-накопителей

**8. NTFS:**
- Файловая система Windows
- Поддержка в Linux через драйверы
- Хорошо для обмена данными с Windows

**Просмотр файловых систем:**
```bash
# Список смонтированных ФС
df -h
df -hT  # с типами

# Информация о блочных устройствах
lsblk

# Детальная информация
mount
cat /proc/mounts
```

**Создание файловой системы:**
```bash
# ext4
sudo mkfs.ext4 /dev/sdb1

# XFS
sudo mkfs.xfs /dev/sdb1

# С меткой
sudo mkfs.ext4 -L "mydata" /dev/sdb1
```

**Монтирование:**
```bash
# Временное монтирование
sudo mount /dev/sdb1 /mnt/data

# Постоянное монтирование (в /etc/fstab)
/dev/sdb1 /mnt/data ext4 defaults 0 2
```

### Первичное монтирование диска при установке системы

**Первичное монтирование** - процесс разметки диска и создания файловых систем при установке Linux. Существует два основных подхода: без LVM (традиционный) и с LVM (логическое управление томами).

#### Разметка диска без LVM (традиционная)

**Структура разделов:**

При установке создаются разделы на физическом диске, которые монтируются напрямую.

**Типичная схема разделов:**
```
/dev/sda1  - /boot      (500MB-1GB)   - загрузочный раздел
/dev/sda2  - swap       (2GB-8GB)     - раздел подкачки
/dev/sda3  - /          (остальное)   - корневая файловая система
# или
/dev/sda3  - /          (20-30GB)     - корневая ФС
/dev/sda4  - /home      (остальное)   - домашние директории
```

**Процесс разметки при установке:**

**Шаг 1: Выбор диска**
- Выбрать диск для установки (например, `/dev/sda`)

**Шаг 2: Создание таблицы разделов**
- **MBR (Master Boot Record)** - старый стандарт, до 2TB, максимум 4 основных раздела
- **GPT (GUID Partition Table)** - современный стандарт, >2TB, неограниченное количество разделов (рекомендуется)

**Шаг 3: Создание разделов**

**Раздел 1: /boot (загрузочный)**
- Размер: 500MB - 1GB
- Тип: Primary/EFI System Partition
- Файловая система: ext4
- Точка монтирования: `/boot`
- Зачем: хранит ядро Linux и загрузчик (GRUB)

**Раздел 2: swap (подкачка)**
- Размер: обычно 2x RAM (или меньше для больших RAM >16GB)
- Тип: Linux swap
- Файловая система: swap
- Точка монтирования: `swap`
- Зачем: виртуальная память на диске, используется когда не хватает RAM

**Раздел 3: / (корневая файловая система)**
- Размер: минимум 20GB, рекомендуется 30-50GB для серверов
- Тип: Linux filesystem
- Файловая система: ext4 (или XFS)
- Точка монтирования: `/`
- Зачем: операционная система, программы, системные файлы

**Раздел 4: /home (опционально)**
- Размер: остальное пространство
- Тип: Linux filesystem
- Файловая система: ext4
- Точка монтирования: `/home`
- Зачем: пользовательские данные отдельно от системы, упрощает переустановку

**Пример конфигурации /etc/fstab (без LVM):**
```bash
# Без LVM
UUID=xxx-xxx-xxx    /              ext4    defaults        0       1
UUID=yyy-yyy-yyy    /boot          ext4    defaults        0       2
UUID=zzz-zzz-zzz    /home          ext4    defaults        0       2
UUID=aaa-aaa-aaa    swap           swap    defaults        0       0
```

**Преимущества без LVM:**
- Простота понимания и управления
- Прямой доступ к разделам
- Меньше слоев абстракции
- Быстрее для простых случаев
- Меньше точек отказа

**Недостатки без LVM:**
- Сложно изменить размер разделов (требует переразметки)
- Нужно планировать размеры заранее
- Сложно добавлять диски в существующую структуру
- Риск потери данных при изменении разделов
- Нет возможности создавать снимки (snapshots)

#### Разметка диска с LVM (Logical Volume Manager)

**Концепция LVM:**

LVM добавляет уровень абстракции между физическими дисками и файловыми системами, обеспечивая гибкость управления дисковым пространством.

**Три уровня LVM:**
1. **PV (Physical Volume)** - физические тома (диски или разделы)
2. **VG (Volume Group)** - группа томов (объединение нескольких PV)
3. **LV (Logical Volume)** - логические тома (виртуальные разделы для файловых систем)

**Структура с LVM:**
```
Физический диск (/dev/sda)
    ↓
Разделы (Partitions)
    ↓
Физические тома (PV) - /dev/sda1, /dev/sda2
    ↓
Группа томов (VG) - vg0
    ↓
Логические тома (LV) - lv-root, lv-home, lv-swap
    ↓
Файловые системы (ext4, xfs)
    ↓
Точки монтирования (/ , /home, swap)
```

**Процесс разметки с LVM при установке:**

**Шаг 1: Создание базовых разделов**

```bash
# Минимальная схема:
/dev/sda1  - /boot      (500MB-1GB)   - загрузочный (БЕЗ LVM!)
/dev/sda2  - LVM PV     (остальное)   - весь диск для LVM
```

**Важно:** `/boot` всегда должен быть БЕЗ LVM, так как загрузчик должен видеть раздел напрямую!

**Шаг 2: Создание Physical Volume (PV)**

```bash
# Установщик автоматически создает:
pvcreate /dev/sda2

# Проверка
pvs
# Вывод: PV         VG   Fmt  Attr PSize   PFree
#        /dev/sda2  vg0  lvm2 a--  100.00g 0
```

**Шаг 3: Создание Volume Group (VG)**

```bash
# Установщик создает группу томов:
vgcreate vg0 /dev/sda2

# Проверка
vgs
# Вывод: VG   #PV #LV #SN Attr   VSize   VFree
#        vg0    1   3   0 wz--n- 100.00g 0
```

**Шаг 4: Создание Logical Volumes (LV)**

```bash
# Установщик создает логические тома:

# 1. Swap
lvcreate -L 4G -n lv-swap vg0
# Размер: 4GB
# Имя: lv-swap

# 2. Root (корневая ФС)
lvcreate -L 30G -n lv-root vg0
# Размер: 30GB
# Имя: lv-root

# 3. Home (домашние директории)
lvcreate -l 100%FREE -n lv-home vg0
# Размер: все оставшееся пространство
# Имя: lv-home

# Проверка
lvs
# Вывод: LV       VG   Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
#        lv-home  vg0  -wi-ao----  66.00g
#        lv-root  vg0  -wi-ao----  30.00g
#        lv-swap  vg0  -wi-ao----   4.00g
```

**Шаг 5: Создание файловых систем**

```bash
# Установщик форматирует логические тома:

# Root
mkfs.ext4 /dev/vg0/lv-root
# или
mkfs.ext4 /dev/mapper/vg0-lv-root

# Home
mkfs.ext4 /dev/vg0/lv-home

# Swap
mkswap /dev/vg0/lv-swap
swapon /dev/vg0/lv-swap
```

**Шаг 6: Монтирование**

```bash
# Установщик монтирует тома:
mount /dev/vg0/lv-root /mnt
mount /dev/vg0/lv-home /mnt/home
mount /dev/sda1 /mnt/boot
```

**Пример конфигурации /etc/fstab (с LVM):**
```bash
# С LVM
UUID=xxx-xxx-xxx    /              ext4    defaults        0       1
UUID=yyy-yyy-yyy    /boot          ext4    defaults        0       2
UUID=zzz-zzz-zzz    /home          ext4    defaults        0       2
/dev/mapper/vg0-lv-swap  none     swap    sw              0       0
# или по UUID
UUID=aaa-aaa-aaa    none           swap    sw              0       0
```

**Преимущества LVM:**
- **Гибкость:** легко изменять размер томов без переразметки
- **Расширяемость:** легко добавлять новые диски в группу томов
- **Снимки (snapshots):** создание резервных копий файловых систем
- **Объединение дисков:** несколько физических дисков в одну логическую группу
- **Миграция данных:** перенос данных между дисками без простоя
- **Удобное резервное копирование:** снимки можно монтировать отдельно

**Недостатки LVM:**
- Сложнее для понимания новичками
- Дополнительный слой абстракции (небольшой overhead)
- Требует больше знаний для управления
- Восстановление данных сложнее при проблемах с LVM

#### Сравнение подходов

**Без LVM (традиционный):**
```
/dev/sda1 → /boot
/dev/sda2 → swap
/dev/sda3 → /
/dev/sda4 → /home
```

**Управление:**
```bash
# Просмотр разделов
fdisk -l
lsblk

# Изменение размера (сложно, рискованно)
# Требует переразметки, риск потери данных
```

**С LVM (гибкий):**
```
/dev/sda1 → /boot
/dev/sda2 → PV → VG (vg0) → LV (lv-root) → /
                              → LV (lv-home) → /home
                              → LV (lv-swap) → swap
```

**Управление:**
```bash
# Просмотр структуры
pvs    # физические тома
vgs    # группы томов
lvs    # логические тома
lsblk  # вся структура

# Изменение размера (легко, безопасно)
lvextend -L +10G /dev/vg0/lv-root
resize2fs /dev/vg0/lv-root
```

#### Типичные схемы разметки

**Схема 1: Минимальная (без LVM)**
```
/boot  - 500MB  (ext4)
swap   - 2GB   (swap)
/      - остальное (ext4)
```
Подходит для: простых серверов, виртуальных машин, тестовых систем.

**Схема 2: Стандартная (без LVM)**
```
/boot  - 500MB  (ext4)
swap   - 4GB    (swap)
/      - 30GB   (ext4)
/home  - остальное (ext4)
```
Подходит для: рабочих станций, серверов с пользователями.

**Схема 3: С LVM (гибкая)**
```
/boot      - 500MB  (ext4, БЕЗ LVM)
LVM PV     - остальное
  ├─ lv-root  - 30GB  (ext4) → /
  ├─ lv-home  - 50GB  (ext4) → /home
  ├─ lv-var   - 20GB  (ext4) → /var
  └─ lv-swap  - 4GB   (swap)  → swap
```
Подходит для: продакшн серверов, систем, требующих гибкости.

**Схема 4: Расширенная (с LVM, несколько дисков)**
```
Диск 1 (/dev/sda):
  /boot - 500MB
  LVM PV - остальное

Диск 2 (/dev/sdb):
  LVM PV - весь диск

VG (vg0) объединяет оба диска:
  ├─ lv-root  - 50GB  → /
  ├─ lv-home  - 100GB → /home
  ├─ lv-data  - остальное → /data
  └─ lv-swap  - 8GB   → swap
```
Подходит для: серверов с несколькими дисками, систем хранения данных.

#### Команды для работы с LVM

**Просмотр структуры:**
```bash
# Физические тома
pvs
pvdisplay

# Группы томов
vgs
vgdisplay

# Логические тома
lvs
lvdisplay

# Вся структура
lsblk
```

**Расширение логического тома:**
```bash
# 1. Расширить логический том
lvextend -L +10G /dev/vg0/lv-root
# или использовать весь свободный объем
lvextend -l +100%FREE /dev/vg0/lv-root

# 2. Расширить файловую систему
resize2fs /dev/vg0/lv-root
# для XFS:
xfs_growfs /dev/vg0/lv-root
```

**Добавление нового диска в LVM:**
```bash
# 1. Создать физический том
pvcreate /dev/sdb

# 2. Расширить группу томов
vgextend vg0 /dev/sdb

# 3. Теперь можно расширять логические тома
lvextend -l +100%FREE /dev/vg0/lv-data
resize2fs /dev/vg0/lv-data
```

**Создание снимка (snapshot):**
```bash
# Создать снимок логического тома
lvcreate -L 5G -s -n lv-root-snapshot /dev/vg0/lv-root

# Монтировать снимок
mount /dev/vg0/lv-root-snapshot /mnt/snapshot

# Удалить снимок
lvremove /dev/vg0/lv-root-snapshot
```

#### Рекомендации по выбору

**Используй БЕЗ LVM, если:**
- Простая система с одним диском
- Размеры разделов известны заранее и не будут меняться
- Нужна простота управления
- Виртуальная машина с фиксированным размером диска
- Обучающая система для понимания основ

**Используй С LVM, если:**
- Нужна гибкость изменения размеров разделов
- Несколько физических дисков
- Планируется расширение дискового пространства
- Нужны снимки файловых систем (snapshots)
- Продакшн сервер с требованиями к масштабированию
- Система хранения данных

#### Важные моменты

1. **/boot всегда БЕЗ LVM:** загрузчик должен видеть раздел напрямую
2. **Размер swap:** обычно 2x RAM, но для больших RAM (16GB+) можно меньше или равный RAM
3. **Размер /:** минимум 20GB, рекомендуется 30-50GB для серверов
4. **UUID vs /dev/sdX:** в `/etc/fstab` лучше использовать UUID для стабильности
5. **Резервное копирование:** перед изменением разделов всегда делать бэкап
6. **Тестирование:** тестировать изменения на тестовых системах перед продакшеном

#### 2.3. Специальные File Systems

**1. /proc (procfs):**
- Виртуальная файловая система
- Информация о процессах и системе
- Файлы создаются ядром динамически
- `/proc/cpuinfo` - информация о процессоре
- `/proc/meminfo` - информация о памяти
- `/proc/version` - версия ядра

**2. /sys (sysfs):**
- Виртуальная файловая система
- Информация об устройствах и драйверах
- Интерфейс для управления ядром
- Появилась в Linux 2.6

**3. /dev (devfs):**
- Файлы устройств
- Блочные устройства (`/dev/sda`, `/dev/sdb`)
- Символьные устройства (`/dev/tty`, `/dev/null`)
- Создаются динамически через udev

**4. /tmp (tmpfs):**
- Временные файлы в RAM
- Быстрый доступ
- Очищается при перезагрузке
- Ограничение размера

**5. /run (tmpfs):**
- Временные файлы рантайма
- PID файлы, сокеты
- Очищается при перезагрузке

**6. /dev/shm (tmpfs):**
- Разделяемая память
- Для межпроцессного взаимодействия
- Обычно половина RAM

#### 2.4. Возможные типы файлов Linux

**Определение типа файла:**
```bash
file filename
ls -l filename
stat filename
```

**Типы файлов:**

**1. Обычный файл (-):**
- Текстовые файлы, бинарные файлы
- Любые данные
- Самый распространенный тип

**2. Директория (d):**
- Содержит другие файлы
- Специальный тип файла в Linux
- Права доступа как у обычных файлов

**3. Символическая ссылка (l):**
- Указатель на другой файл
- Создается командой `ln -s`
- Может указывать на несуществующий файл

**4. Блочное устройство (b):**
- Диски, разделы
- Доступ по блокам
- Пример: `/dev/sda`, `/dev/sdb1`

**5. Символьное устройство (c):**
- Терминалы, принтеры
- Доступ посимвольно
- Пример: `/dev/tty`, `/dev/null`

**6. Именованный канал / FIFO (p):**
- Межпроцессное взаимодействие
- Однонаправленная передача
- Создается `mkfifo`

**7. Сокет (s):**
- Сетевое взаимодействие
- Межпроцессное взаимодействие
- Пример: `/var/run/docker.sock`

**Работа с символическими ссылками:**
```bash
# Создание
ln -s /path/to/target link_name

# Просмотр куда указывает
readlink link_name
ls -l link_name

# Удаление
rm link_name  # удаляет только ссылку, не файл
```

**Работа с жесткими ссылками:**
```bash
# Создание
ln target hardlink

# Особенности:
# - Одинаковый inode
# - Удаление одного не удаляет другой
# - Работает только в пределах одной ФС
```
