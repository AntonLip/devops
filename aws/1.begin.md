# 1. Что такое cloud computing

Cloud computing - модель, в которой инфраструктура и платформенные сервисы предоставляются по требованию через API. В классическом дата-центре команда заранее покупает серверы, сетевое оборудование, стойки, питание и лицензии. В облаке большая часть этого превращается в управляемый сервис: ресурсы можно создать за минуты, масштабировать, удалить и оплатить только фактическое потребление.

Для DevOps облако важно не потому, что «серверы где-то ещё», а потому что почти всё становится **программируемым**:

- VM создаются через API;
- сеть описывается правилами и маршрутами;
- права доступа задаются policy;
- логи, метрики и события доступны как сервис;
- инфраструктуру можно версионировать через Terraform/CloudFormation;
- CI/CD может создавать тестовые окружения автоматически.

Главная идея: облако превращает инфраструктуру в набор сервисов с API, SLA, квотами и моделью оплаты.

## Shared Responsibility Model

AWS отвечает за **security of the cloud**: физические дата-центры, стойки, питание, сеть AWS, hypervisor, базовую инфраструктуру сервисов.
Пользователь отвечает за **security in the cloud**:
- IAM users, roles, policies;
- сетевые правила Security Groups/NACL;
- шифрование данных там, где оно настраивается клиентом;
- обновления ОС на EC2;
- секреты приложения;
- backup и retention;
- публичность S3 bucket;
- корректную архитектуру отказоустойчивости.
Чем выше уровень сервиса, тем больше операционной работы забирает AWS. На EC2 пользователь отвечает за ОС. В RDS AWS управляет ОС базы, но не проектирует схему и доступы. В Lambda AWS управляет серверами, но пользователь отвечает за код, IAM и события.

## Regions, Availability Zones, Edge Locations

**Region** — географический регион AWS, например `eu-central-1` или `us-east-1`. Большинство ресурсов создаётся в конкретном регионе.
**Availability Zone (AZ)** — изолированная зона внутри региона. Обычно это один или несколько дата-центров с независимым питанием и сетью. Сервисы высокой доступности распределяют ресурсы между AZ.
**Edge Location** — точка присутствия для доставки контента и edge-сервисов, например CloudFront.
Практические выводы:
- EC2 instance находится в конкретной AZ.
- S3 bucket создаётся в регионе, но сам сервис проектируется как регионально отказоустойчивый.
- RDS Multi-AZ повышает доступность базы.
- ALB и Auto Scaling обычно размещают ресурсы в нескольких AZ.
- Выбор региона влияет на latency, стоимость, доступность сервисов и требования по хранению данных.

## Глобальные и региональные сервисы

Не все AWS-сервисы устроены одинаково.
Глобальные или почти глобальные:
- IAM;
- Route 53;
- CloudFront;
- AWS Organizations.
Региональные:
- EC2;
- VPC;
- RDS;
- Lambda;
- CloudWatch;
- S3 bucket создаётся с региональной привязкой.

Прежде чем использовать сервис вы должны понимать региональный или глобальный сервис, на каком уровне создается сервим (s3 на уровне региона, ec2 на уровне зоны доступности) и помните о том как производиться конечный расчет стоимости сервиса.

## IaaS, PaaS, SaaS

| Модель   | Что контролирует пользователь                   | AWS-примеры                                            |
| -------- | ----------------------------------------------- | ------------------------------------------------------ |
| **IaaS** | ОС, runtime, приложения, часть сетевых настроек | EC2, EBS, VPC                                          |
| **PaaS** | приложение и настройки сервиса                  | RDS, Elastic Beanstalk, ECS Fargate, Lambda частично   |
| **SaaS** | только использование готового продукта          | Amazon Chime, QuickSight, сторонние SaaS в Marketplace |

На практике границы не всегда идеальны. Например, **RDS** управляет ОС, патчами и backup-механикой базы, но пользователь всё равно отвечает за схему БД, пользователей, доступы, параметры и стоимость. **Lambda** убирает управление сервером, но оставляет ответственность за код, IAM role, timeout, memory, retries и обработку ошибок.

## Способы взаимодействия с облаком

**AWS Console** — веб-интерфейс. Он удобен для знакомства, поиска настроек и разовых действий.
**AWS CLI и API** важнее для инженерной работы:
- действия можно повторить;
- команды можно добавить в документацию;
- инфраструктуру проще автоматизировать;
- ошибки проще воспроизвести;
- CI/CD не должен кликать в Console.

Правильная траектория обучения: сначала понять сервис через Console, затем повторить ключевые действия через CLI/API, затем описывать инфраструктуру кодом.

## AWS billing
Оплата сервисов основана на потреблении: время работы, объём данных, запросы, storage, traffic, managed service capacity. Даже маленькая лаборатория может стоить денег, если забыть ресурсы.
Минимальные правила:

- включить MFA на root account;
- создать budget alert;
- проверять Billing Dashboard после лабораторных;
- удалять ресурсы после практики;
- использовать tags: `Course`, `Owner`, `Environment`;
- не запускать большие instance types;
- не оставлять NAT Gateway, RDS и Load Balancer без необходимости.

Особенно внимательно относитесь к NAT Gateway, RDS, ALB и публичным IP: они могут генерировать стоимость даже при низкой нагрузке.

# 2. Основные сервисы AWS

AWS - это не один продукт, а **более 200 сервисов**. Ниже - карта основных сервисов с пояснением, что каждый делает и где он встретится дальше.

## Карта сервисов по категориям

| Категория | Сервисы | Роль в DevOps |
|-----------|---------|---------------|
| **Identity & Access** | IAM, STS, Organizations | Кто может что делать в account |
| **Compute** | EC2, Lambda, ECS, EKS | Где выполняется код |
| **Storage** | S3, EBS, EFS | Где хранятся файлы, образы, артефакты |
| **Database** | RDS, DynamoDB | Управляемые базы данных |
| **Networking** | VPC, Route 53, ALB/NLB, CloudFront, NAT Gateway | Сеть, DNS, балансировка, CDN |
| **Integration** | SQS, SNS, EventBridge | Очереди, pub/sub, события |
| **Observability** | CloudWatch, CloudTrail, X-Ray | Метрики, логи, аудит |
| **Security** | KMS, Secrets Manager, WAF, Shield | Шифрование, секреты, защита периметра |
| **Management** | CloudFormation, Systems Manager, Config | IaC, управление fleet, compliance |

---

### Identity & Access

#### IAM (Identity and Access Management)

**Что это:** глобальный сервис управления доступом. Определяет, **кто** (users, roles, services) может выполнять **какие действия** над **какими ресурсами**.
**Ключевые сущности:**
- **User** - identity для человека или legacy-интеграции;
- **Group** - контейнер для policy, не principal;
- **Role** - identity без пароля; принимается через STS;
- **Policy** - JSON-документ с `Allow`/`Deny` для actions и resources.
**Модель:** default deny - без явного разрешения доступ запрещён.
**Тарификация:** бесплатно.

#### STS (Security Token Service)

**Что это:** выдаёт **временные credentials** (access key + secret + session token) с ограниченным сроком жизни.
**Где используется:**
- EC2 instance profile;
- Lambda execution role;
- `aws sts assume-role` для cross-account;
- federated login через OIDC/SAML.
**Тарификация:** бесплатно.

#### AWS Organizations

**Что это:** управление несколькими AWS account из одной организации. Позволяет consolidated billing, создавать OU (organizational units) и применять **SCP (Service Control Policies)** - guardrails сверх IAM.
**Когда нужен:** enterprise с десятками account, Landing Zone, разделение prod/staging/dev по account.
**Тарификация:** бесплатно (платите только за ресурсы в member accounts).

---

#### Compute

##### EC2 (Elastic Compute Cloud)

**Что это:** виртуальные машины в облаке. Основной **IaaS**-сервис AWS.
**Ключевые понятия:**
- **Instance** - VM с CPU, RAM, сетью;
- **AMI (Amazon Machine Image)** - шаблон диска для запуска instance;
- **Instance type** - размер (например, `t3.micro`, `m6i.large`);
- **Key pair** - пара SSH-ключей доступ доступа к виртуальной машине;
- **User data** - скрипт при первом запуске;
- **Security Group** - firewall на уровне instance.

**Модели оплаты:** On-Demand, Reserved, Spot.
**Ответственность клиента:** ОС, патчи, runtime, приложение, firewall rules.
**Тарификация:** за секунды/часы работы instance + attached EBS + public IP + исходящий traffic.

##### Lambda

**Что это:** serverless compute - запускает функцию по событию без управления серверами.
**Ключевые понятия:**
- **Function** - код + runtime (Python, Node.js, Go…);
- **Trigger** - S3 event, API Gateway, EventBridge, SQS;
- **Execution role** - IAM role с permissions функции;
- **Timeout, memory** - лимиты выполнения;
- **Cold start** - задержка при первом вызове после простоя.
**Когда использовать:** короткие event-driven задачи, API backends, обработка файлов, cron через EventBridge.
**Тарификация:** за количество вызовов + GB-секунды памяти.

##### ECS / EKS (кратко)

**ECS (Elastic Container Service)** - оркестратор контейнеров AWS. Запускает Docker-контейнеры на EC2 или **Fargate** (serverless containers).
**EKS (Elastic Kubernetes Service)** - managed Kubernetes. AWS управляет control plane, вы - worker nodes или Fargate profiles.
**На курсе:** упоминаются как следующий шаг после EC2; детально не разбираются.

---

#### Storage

##### S3 (Simple Storage Service)
**Что это:** объектное хранилище. Файлы (объекты) лежат в **bucket** по ключам (`s3://bucket/path/file.txt`).
**Ключевые понятия:**
- **Bucket** - контейнер с глобально уникальным именем, привязан к региону;
- **Object** - файл + metadata;
- **Storage class** - Standard, Infrequent Access, Glacier (архив);
- **Versioning** - хранение версий объекта;
- **Lifecycle rules** - автоматический переход/удаление;
- **Bucket policy** - resource-based policy доступа;
- **Block Public Access** - защита от случайной публичности.

**Типичные use cases:** статика сайтов, backup, CI/CD artifacts, data lake, логи.
**Тарификация:** GB-month storage + requests (PUT/GET/LIST) + data transfer out.

##### EBS (Elastic Block Store)
**Что это:** блочное хранилище - диск, который подключается к EC2 instance (как `/dev/xvda`).
**Ключевые понятия:**
- **Volume** - диск определённого размера и типа (`gp3`, `io2`);
- **Snapshot** - backup volume в S3;
- **Привязка к AZ** - volume живёт в одной AZ; перенос через snapshot.

**Когда использовать:** системный диск EC2, базы данных на EC2, любые данные, требующие низкой latency к одной VM.
**Тарификация:** GB-month, пока volume существует (даже без attached instance).

##### EFS (Elastic File System)

**Что это:** managed **NFS** - общая файловая система, которую могут монтировать несколько EC2 одновременно.
**Когда использовать:** shared storage между instances, CMS с общими файлами, legacy-приложения на NFS.
**Тарификация:** GB-month + throughput (зависит от режима).

---

#### Database

##### RDS (Relational Database Service)

**Что это:** managed реляционная БД. AWS управляет установкой, патчами, backup-механикой; вы выбираете engine и параметры.
**Поддерживаемые engines:** PostgreSQL, MySQL, MariaDB, Oracle, SQL Server, Aurora.
**Ключевые понятия:**
- **DB instance** - managed сервер БД;
- **Multi-AZ** - standby-копия в другой AZ для failover;
- **Read Replica** - read-only копия для масштабирования чтения;
- **Automated backups** - point-in-time recovery;
- **Parameter group / subnet group** - конфигурация и сеть.

**Тарификация:** instance hours + storage + backup storage + I/O (зависит от engine).

##### DynamoDB (кратко)

**Что это:** managed NoSQL key-value/document database. Serverless, автоматическое масштабирование, single-digit millisecond latency.
**Когда использовать:** высоконагруженные key-value workloads, session storage, gaming leaderboards.
**Тарификация:** on-demand (за запрос) или provisioned capacity (RCU/WCU).

---

#### Networking

##### VPC (Virtual Private Cloud)

**Что это:** изолированная виртуальная сеть в AWS. Всё, что вы создаёте (EC2, RDS, Lambda в VPC), живёт внутри VPC.
**Ключевые понятия:**
- **CIDR block** - диапазон IP (например, `10.0.0.0/16`);
- **Subnet** - подсеть внутри AZ (public или private);
- **Route table** - куда направлять traffic;
- **Internet Gateway (IGW)** - выход в интернет для public subnet;
- **NAT Gateway** - исходящий интернет для private subnet;
- **Security Group** - stateful firewall на уровне instance/ENI;
- **NACL** - stateless firewall на уровне subnet.

##### Route 53

**Что это:** DNS-сервис и health checking. **Глобальный** сервис.
**Возможности:**
- регистрация и управление доменами;
- DNS records (A, CNAME, MX, alias на AWS resources);
- routing policies (weighted, latency-based, failover);
- health checks для автоматического переключения.

**Тарификация:** hosted zones + queries + health checks.

##### ALB / NLB (Elastic Load Balancing)

**ALB (Application Load Balancer)** - балансировка HTTP/HTTPS на уровне L7. Поддерживает path-based routing, host-based routing, integration с ECS/EKS/Lambda.
**NLB (Network Load Balancer)** - балансировка TCP/UDP на уровне L4. Низкая latency, static IP, millions of requests/sec.
**Тарификация:** почасовая плата + LCU (load balancer capacity units) - один из «пожирателей бюджета».

##### CloudFront

**Что это:** CDN (Content Delivery Network). Кэширует контент на **Edge Locations** по всему миру.
**Когда использовать:** раздача статики, ускорение API, защита origin через WAF.
**Тарификация:** data transfer out + requests.

##### NAT Gateway

**Что это:** managed NAT для private subnet - instances без public IP могут выходить в интернет (обновления, API calls), но inbound из интернета к ним не проходит.
**Важно:** дорогой ресурс - почасовая плата + плата за каждый GB traffic. После лабораторий удалять.

---

#### Integration & Messaging

##### SQS (Simple Queue Service)

**Что это:** managed очередь сообщений. Producer кладёт сообщение, consumer забирает и обрабатывает.
**Паттерны:** decoupling сервисов, буферизация нагрузки, retry через DLQ (Dead Letter Queue).
**Тарификация:** за количество requests.

##### SNS (Simple Notification Service)

**Что это:** pub/sub - одно сообщение рассылается многим подписчикам (email, SMS, Lambda, SQS, HTTP).
**Когда использовать:** алерты, fan-out событий, уведомления.

##### EventBridge

**Что это:** event bus - маршрутизация событий между AWS-сервисами и внешними источниками по правилам (rules).
**Примеры событий:** S3 upload, EC2 state change, scheduled cron, custom application events.

##### API Gateway

**Что это:** managed HTTP/WebSocket API. Принимает запросы из интернета и проксирует в Lambda, EC2, другие сервисы.
**Возможности:** auth (IAM, Cognito, API keys), throttling, caching, custom domains.
**Тарификация:** за количество API calls.

---

#### Observability & Audit

##### CloudWatch

**Что это:** мониторинг и observability-платформа AWS.
**Компоненты:**

- **Metrics** - CPU, memory, custom metrics;
- **Logs** - централизованные логи (Lambda, EC2 agent, application logs);
- **Alarms** - alert при превышении порога;
- **Dashboards** - визуализация метрик.

**Тарификация:** custom metrics, log ingestion/storage, alarms - платно; базовые EC2 metrics - бесплатно.

##### CloudTrail

**Что это:** аудит **API-вызовов** в AWS account. Записывает, кто, когда и какой API вызвал (`RunInstances`, `PutObject`, `DeleteBucket`…).
**Зачем DevOps:** расследование инцидентов, compliance, обнаружение несанкционированных действий.
**Тарификация:** первый trail в регионе - бесплатно; доставка в S3 - storage costs.

---

#### Security

##### KMS (Key Management Service)

**Что это:** управление ключами шифрования. Шифрует EBS, S3, RDS, Secrets Manager и другие сервисы.
**Тарификация:** за ключ + API calls к KMS.

##### Secrets Manager / SSM Parameter Store

**Secrets Manager** - хранение секретов (пароли БД, API keys) с автоматической rotation.
**SSM Parameter Store** - конфигурация и секреты (Standard - бесплатно, Advanced - платно).
**Правило:** не хранить секреты в коде, Git или user data в открытом виде.

##### WAF / Shield

**WAF (Web Application Firewall)** - фильтрация HTTP-запросов (SQL injection, XSS) на ALB/CloudFront/API Gateway.
**Shield** - DDoS-защита (Standard бесплатно, Advanced - платная подписка).

---

##### AWS Config

**Что это:** отслеживает конфигурацию ресурсов и проверяет compliance rules (например, «все S3 bucket должны быть encrypted»).

# 3. Рекомендации перед началом практики 

Если account уже есть, не создавайте новый без необходимости. Проверьте:
- есть доступ к root email;
- включён MFA;
- есть доступ к Billing;
- account не используется для production.

Если создаёте новый account:

1. Зарегистрируйтесь на [aws.amazon.com](https://aws.amazon.com/).
2. Укажите платёжную карту.
3. Подтвердите телефон.
4. Выберите Basic support plan.

**Важно:** root account используется только для первичной настройки и критических административных операций. Для повседневной работы нужен отдельный IAM-доступ

## 3.1 Включить MFA для root

1. Войдите как root user.
2. Откройте **IAM** → **Security recommendations** или **My Security Credentials**.
3. Найдите **Multi-factor authentication (MFA)**.
4. Добавьте virtual MFA device.
5. Сохраните recovery-коды/настройки в надёжном месте.

**Проверка:** выйдите из account и войдите снова. AWS должен запросить MFA-код.

## 3.2 Настроить budget alert

1. Откройте **Billing and Cost Management**.
2. Перейдите в **Budgets**.
3. Создайте **Cost budget**.
4. Тип: monthly cost budget.
5. Лимит для лаборатории: например **5 USD** или **10 USD**.
6. Alert: 80% и 100% от бюджета.
7. Email: ваш рабочий email.

Budget не останавливает ресурсы автоматически, но предупреждает о расходах.

## 3.4. Выбрать регион курса

Для курса выберите один основной регион и используйте его во всех практиках. Например:

- `eu-central-1` — Frankfurt;
- `eu-west-1` — Ireland;
- `us-east-1` — N. Virginia, часто самый полный по сервисам.

Критерии выбора:
- сервисы из курса доступны;
- latency до вас приемлемая;
- стоимость понятна;
- нет внутренних требований по data residency.

Запишите выбранный регион и работайте только в нем.
