# Архитектура хранения данных

## Цель

Понять **зачем Kubernetes разделяет ephemeral и persistent storage**; различить **emptyDir**, **hostPath**, **CSI** и облачные/сетевые бэкенды; на **реальном Talos homelab**
---

## Теория

### Зачем вообще нужны volumes

Контейнер по умолчанию пишет в **writable layer** образа. Этот слой:
- живёт вместе с контейнером;
- **не переживает** удаление Pod;
- при **recreate** Pod на другом node — данные теряются;
- не шарится между контейнерами одного Pod без общего mount.
**Volume** — абстракция Kubernetes: «подключи этому Pod каталог/диск из другого источника». Источник может быть эфемерным (emptyDir) или персистентным (PV/NFS/EBS).

```
┌─────────────────────────────────────────────────────────────┐
│                         Pod                                  │
│  ┌──────────────┐    volumeMount      ┌──────────────────┐  │
│  │  Container   │ ─────────────────► │  Volume (spec)   │  │
│  │  /app/data   │                      │  emptyDir / PVC  │  │
│  └──────────────┘                      └────────┬─────────┘  │
└─────────────────────────────────────────────────┼────────────┘
                                                  │
                    ┌─────────────────────────────┼─────────────────────────────┐
                    │                             ▼                             │
                    │  Ephemeral: node RAM/disk    Persistent: PV → disk/NFS     │
                    └─────────────────────────────────────────────────────────────┘
```

**На собеседовании:** «Данные в контейнере сохраняются после restart?» — **да**, если тот же Pod на том же node. После **delete Pod** — **нет**, если не используется persistent volume.

---

### Ephemeral vs Persistent

| Критерий | Ephemeral | Persistent |
|----------|-----------|------------|
| **Жизненный цикл** | Создаётся с Pod, удаляется с Pod | Переживает Pod |
| **Примеры** | emptyDir, configMap, secret, projected | PV + PVC, CSI volume |
| **Use case** | cache, temp files, конфиги | БД, файловое хранилище, логи long-term |
| **Backup** | Обычно не нужен | Snapshots, Velero, репликация |
| **Multi-node** | Привязан к node Pod | Зависит от accessMode и бэкенда |

```
Ephemeral lifecycle:

  Pod CREATE ──► emptyDir CREATE on node
       │
       │  Pod RUNNING — данные в /scratch
       │
  Pod DELETE ──► emptyDir DELETE (данные потеряны)


Persistent lifecycle:

  Admin/CSI ──► PV CREATE (диск существует)
       │
  User ──► PVC CREATE ──► BIND ──► Pod mount
       │
  Pod DELETE ──► PV остаётся (reclaimPolicy!)
       │
  PVC DELETE ──► Retain / Recycle / Delete
```

### emptyDir

**Зачем появился:** нужен был **общий каталог между контейнерами** одного Pod без внешнего storage.
**Как работает:** kubelet создаёт пустую директорию на **node** (диск или `medium: Memory` — tmpfs).
**Ограничения:**
- данные **не** переживают Pod;
- при reschedule на другой node — **новый** emptyDir;
- `sizeLimit` — eviction при превышении (если задан).

**Production:** sidecar для логов, scratch для sort, Istio/Envoy buffer — типичные кейсы.

---

### hostPath

**Зачем:** до CSI/PVC админы монтировали **путь на node** напрямую.
**Как работает:** kubelet монтирует `spec.volumes.hostPath.path` с node в Pod.

```
Node filesystem                    Pod
/var/lib/data  ── hostPath ──►  /data (container)
```

**Ограничения и риски:**
- Pod **привязан к node** (данные только там);
- **нет** изоляции — Pod видит host FS (security risk);
- при удалении node — данные потеряны;
- в managed cloud часто **запрещён** PodSecurity.

**Production:** DaemonSet (логи node, Cilium), lab/static PV на homelab. **Не** для stateful apps без жёсткой node affinity.

---

### CSI (Container Storage Interface)

**Зачем появился:** in-tree драйверы (awsElasticBlockStore, gcePersistentDisk) были **в коде Kubernetes** — обновление драйвера = релиз k8s.
**CSI** — стандарт gRPC API: vendor поставляет Controller + Node plugin + sidecars (provisioner, attacher, resizer, snapshotter).

```
                    Kubernetes API
                          │
         ┌────────────────┼────────────────┐
         ▼                ▼                ▼
  external-provisioner  attacher      resizer
         │                │                │
         └────────────────┼────────────────┘
                          ▼
                   CSI Controller Pod
                          │
                          ▼
              Storage backend (EBS, Ceph, NFS…)
                          ▲
                   CSI Node Pod (DaemonSet)
                          ▲
                       kubelet
                          ▲
                        Pod + PVC mount
```

**Ваш homelab:** `kubectl get csidrivers` — **пусто**. Нет CSI Controller/Node pods. Dynamic provisioning **недоступен** до установки, например, **local-path-provisioner** (будет в главе 15.4.5+).

---

### Cloud / Local / Network storage

| Класс | Примеры | Характеристики |
|-------|---------|----------------|
| **Cloud block** | AWS EBS, GCE PD, Azure Disk | RWO, AZ-aware, snapshots через CSI |
| **Cloud file** | AWS EFS, Azure Files | RWX, latency выше block |
| **Local** | hostPath, local-volume, local-path | Низкая latency, нет переносимости между nodes |
| **Network** | NFS, Ceph RBD, Longhorn, Portworx | Shared/cluster storage, зависит от протокола |
| **Object** | S3 (не нативный K8s volume) | через sidecar / CSI (Mountpoint, etc.) |

**Bare metal homelab (Talos):** нет cloud provider → нет автоматического EBS. Варианты:

1. **Static hostPath PV** — lab, одна node;
2. **local-path-provisioner** — pseudo-dynamic на local disk;
3. **NFS/Longhorn/Ceph** — если развернуть отдельно.

### Полная цепочка persistent storage

```
Application
    │
    ▼ volumeMount (/data)
Pod.spec.volumes[]
    │
    ├── emptyDir / configMap / secret  ──► node-local ephemeral
    │
    └── persistentVolumeClaim
              │
              ▼
         PVC (claim)
              │  binding
              ▼
         PV (admin or CSI-created)
              │
              ├── hostPath / local / NFS spec
              │
              └── CSI volumeHandle
                        │
                        ▼
                   Physical / network disk
```

**StorageClass** (нет на вашем кластере) добавляет слой **dynamic provisioning**: PVC без готового PV → provisioner создаёт PV автоматически.

---

### Best practices (production)

| Практика | Почему |
|----------|--------|
| StatefulSet + PVC для БД | stable identity + disk per replica |
| Не хранить state в emptyDir для prod DB | потеря при reschedule |
| Default StorageClass + явный `storageClassName` | предсказуемое поведение |
| `ReadWriteOnce` для block storage | EBS/PV block = один writer |
| Backup через VolumeSnapshot или app-level | PV ≠ backup |
| Topology (zone) для cloud | Pod и disk в одной AZ |
| fsGroup для non-root | права на volume |

**Типичные ошибки:**

- Redis/Postgres на emptyDir в prod «пока не вырастем»;
- hostPath на multi-node без node affinity;
- PVC без StorageClass на кластере без default SC → **Pending forever**;
- `ReadWriteMany` на EBS (не поддерживается).

## Практика

### Цель

Провести **storage audit** на Talos homelab и сравнить **emptyDir в Argo CD** с тем, что дал бы **PVC**.

### Зачем

Без понимания текущего состояния кластера нельзя спланировать persistence. Ваш стенд **намеренно stateless** — это baseline перед лабами в `storage-lab`.

### Шаг 1 — базовый аудит

```bash
kubectl version
kubectl get nodes -o wide
kubectl get sc,pv,pvc -A
kubectl get csidrivers
kubectl get volumesnapshot,volumesnapshotclass -A 2>&1 | head -3
kubectl get nodes -o custom-columns=NAME:.metadata.name,ZONE:.metadata.labels.'topology\.kubernetes\.io/zone'
```

**Ожидаемый результат на вашем кластере:**

| Ресурс | Результат |
|--------|-----------|
| Kubernetes | v1.34.1 |
| Nodes | maste1 + worker-1..3 |
| StorageClass | No resources found |
| PV/PVC | No resources found |
| CSI | No resources found |
| VolumeSnapshot CRD | not installed |
| topology.kubernetes.io/zone | `<none>` на всех nodes |

### Шаг 2 — volumes в production-like namespaces

```bash
# Argo CD
kubectl get pods -n argocd -o json | jq -r '.items[] | select(.spec.volumes) | "\(.metadata.name): \([.spec.volumes[] | keys[0]] | join(", "))"'

# Istio
kubectl get pods -n istio-system -o json | jq -r '.items[] | select(.spec.volumes) | "\(.metadata.name): \([.spec.volumes[] | keys[0]] | unique | join(", "))"'

# devops-lab
kubectl get pods -n devops-lab -o json | jq -r '.items[] | select(.spec.volumes) | "\(.metadata.name): \([.spec.volumes[] | keys[0]] | join(", "))"'
```

**Ожидаемый результат:** emptyDir, configMap, secret, projected — **ни одного** `persistentVolumeClaim`.

### Шаг 3 — детально Argo CD redis vs PVC-сценарий

```bash
kubectl get pod -n argocd -l app.kubernetes.io/name=argocd-redis -o yaml | grep -A5 'volumes:'
kubectl describe pod -n argocd -l app.kubernetes.io/name=argocd-redis | grep -A2 'Volumes:'
```

**Что видим:** redis использует **projected/emptyDir**, не PVC. При удалении Pod или reschedule **кэш redis теряется** (для Argo CD cache это часто acceptable).

**Contrast — если бы нужен PVC:**

```yaml
# Гипотетически (НЕ применять на prod argocd без плана миграции):
volumes:
  - name: redis-data
    persistentVolumeClaim:
      claimName: argocd-redis-pvc
```

Для этого нужны: StorageClass или static PV, reclaim policy, backup strategy — **на вашем кластере пока ничего этого нет**.

### Шаг 4 — подготовка lab namespace

```bash
kubectl apply -f lab/storage-homelab/00-namespace.yaml
kubectl get ns storage-lab
```

Манифест: [`storage-homelab/00-namespace.yaml`](lab/storage-homelab/00-namespace.yaml)

### Verify

```bash
kubectl get ns storage-lab
kubectl get pv,pvc -n storage-lab   # пока empty
```

### Rollback

```bash
kubectl delete ns storage-lab --ignore-not-found
# production namespaces (argocd, istio) — только read-only, не удалять
```

## Что произошло внутри Kubernetes

```
Вы: kubectl get pods -n argocd
         │
         ▼
    API Server (auth: ваш admin cert)
         │
         ▼
    etcd ──► Pod objects с spec.volumes[]
         │
         ▼
    kubectl выводит типы volumes

При RUNNING Pod с emptyDir:
         │
         ▼
    kubelet на node Pod'а
         │
         ├── создаёт /var/lib/kubelet/pods/<uid>/volumes/kubernetes.io~empty-dir/<vol>/
         │
         └── bind-mount в container namespace → volumeMount.mountPath

При отсутствии PVC в spec:
         │
         └── attach/detach controller не участвует (нет PV)
```

## Troubleshooting

| Симптом | Причина | Решение |
|---------|---------|---------|
| `No resources found` для SC/PV | Кластер stateless, CSI не установлен | Ожидаемо; lab static PV в 15.4.3 |
| Argo CD redis «теряет» cache | emptyDir/projected, не PVC | Для lab OK; prod — PVC + backup |
| `error: volumesnapshot not found` | CRD не установлен | Теория в 15.4.5; homelab без snapshots |
| Pod evicted, emptyDir данные gone | emptyDir lifecycle | Использовать PVC для persistence |
| hostPath Pod на wrong node | static binding | nodeSelector / PV nodeAffinity |
| Ожидали AWS EBS | bare metal Talos | local-path / NFS / static hostPath |
