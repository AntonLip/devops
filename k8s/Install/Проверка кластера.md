# Проверка кластера

**Тайминг:** ~30 мин · **Среда:** Ubuntu 24.04 · K8s 1.32.x · `k8s-cp-01` (192.168.1.20) + `k8s-w-01` (192.168.1.21)

---

## Цель

Освоить **полный health-check** kubeadm-кластера: проверить nodes, control plane, system pods, DNS, сеть, events и логи. Понять, какие команды дают **симптом**, а какие - **причину**; собрать чеклист «кластер готов к production-like нагрузке».

---

## Теория

### Зачем отдельная глава про проверку

Установка Kubernetes - это не «зелёный статус одной команды». Кластер может быть **формально инициализирован**, но:

- worker в `NotReady` (нет CNI);
- CoreDNS в `Pending` (нет taints/tolerations или CNI);
- API отвечает, но etcd **degraded**;
- Pod создаётся, но DNS не резолвится.

Проверка - это **многослойная диагностика**: от API до container runtime на каждой node.

### Уровни проверки

```
Уровень 1 - API доступен?
    ↓
Уровень 2 - Nodes Ready?
    ↓
Уровень 3 - Control Plane pods Running?
    ↓
Уровень 4 - Addons (CNI, CoreDNS, kube-proxy) Running?
    ↓
Уровень 5 - Функциональные тесты (DNS, Service, Pod-to-Pod)
    ↓
Уровень 6 - Events, logs, certs, disk
```

### kubectl get nodes

Показывает **регистрацию node** в API и **условия (conditions)** kubelet:

| Поле | Значение |
|------|----------|
| `STATUS` | `Ready` / `NotReady` |
| `ROLES` | `control-plane` / `<none>` |
| `VERSION` | kubelet version (должна совпадать с kubeadm) |
| `INTERNAL-IP` | LAN IP node (192.168.1.2x) |

**Условия node** (смотреть через `describe`):

| Condition | True = |
|-----------|--------|
| `Ready` | Kubelet healthy, CNI configured |
| `MemoryPressure` | Нехватка памяти |
| `DiskPressure` | Мало места на диске |
| `PIDPressure` | Мало PID |
| `NetworkUnavailable` | CNI ещё не настроил сеть |

### kubectl cluster-info

Выводит **endpoint API Server** и **URL Dashboard** (если установлен):

```
Kubernetes control plane is running at https://192.168.1.20:6443
CoreDNS is running at https://192.168.1.20:6443/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy
```

Это **не health-check** - только адреса. Для здоровья нужны дополнительные команды.

### Component health (K8s 1.32+)

`kubectl get componentstatuses` **удалён** в современных версиях. Вместо него:

```bash
# Health endpoints static pods (с control plane node)
curl -k https://127.0.0.1:6443/healthz?verbose
curl -k https://127.0.0.1:6443/livez?verbose
curl -k https://127.0.0.1:6443/readyz?verbose
```

| Endpoint | Что проверяет |
|----------|---------------|
| `/livez` | API Server жив (liveness) |
| `/readyz` | API Server готов принимать трафик |
| `/healthz` | Legacy alias для readyz |

Для etcd, scheduler, controller-manager - смотрим **static pods** в `kube-system`:

```
kube-apiserver-k8s-cp-01
kube-scheduler-k8s-cp-01
kube-controller-manager-k8s-cp-01
etcd-k8s-cp-01
```

### Events - «чёрный ящик» кластера

Kubernetes пишет **Events** при каждом значимом действии: scheduling, pull image, mount volume, probe failed.

```bash
kubectl get events -A --sort-by='.lastTimestamp'
```

Типичные `Reason`:

| Reason | Значение |
|--------|----------|
| `Scheduled` | Pod назначен на node |
| `FailedScheduling` | Нет подходящей node |
| `Pulling` / `Pulled` | Скачивание образа |
| `Failed` | Ошибка (часто kubelet) |
| `Unhealthy` | Probe failed |
| `NodeNotReady` | Node потеряла Ready |

### Логи: три источника

```
kubectl logs <pod>          ← контейнер приложения / addon
journalctl -u kubelet       ← kubelet на node
crictl logs <container-id>  ← через CRI (containerd)
```

На control plane node static pods логируются через kubelet → `kubectl logs -n kube-system kube-apiserver-k8s-cp-01`.

### Полный чеклист здоровья кластера

| # | Проверка | Команда | Ожидание |
|---|----------|---------|----------|
| 1 | API version | `kubectl version` | Server + Client 1.32.x |
| 2 | Nodes Ready | `kubectl get nodes` | Все `Ready` |
| 3 | System pods | `kubectl get pods -n kube-system` | Все Running/Completed |
| 4 | API health | `curl -k https://127.0.0.1:6443/readyz` | `ok` |
| 5 | etcd member | `ETCDCTL_API=3 etcdctl ... endpoint health` | `healthy` |
| 6 | DNS | `kubectl run ... -- nslookup kubernetes` | IP ответа |
| 7 | Pod-to-Pod | ping между test pods | успех |
| 8 | Service | `curl` через ClusterIP | HTTP 200 |
| 9 | Certs expiry | `kubeadm certs check-expiration` | > 30 дней |
| 10 | Disk/etcd | `df -h /var/lib/etcd` | < 80% |
| 11 | Swap | `swapon --show` | пусто |
| 12 | containerd | `systemctl is-active containerd` | active |
| 13 | kubelet | `systemctl is-active kubelet` | active |
| 14 | CNI | `calicoctl node status` или pods calico | Established |
| 15 | Events | `kubectl get events -A` | нет критичных Failed |

## Практика

### Предусловия

Кластер развёрнут по главам  control plane + worker + Calico + CoreDNS.

```bash
# На k8s-cp-01 (192.168.1.20)
export KUBECONFIG=/etc/kubernetes/admin.conf
kubectl get nodes -o wide
```

**Ожидаемый результат:** `k8s-cp-01` Ready, control-plane; `k8s-w-01` Ready.

### Шаг 1 - Версия и cluster-info

```bash
kubectl version --output=yaml
kubectl cluster-info
kubectl cluster-info dump --output-directory=/tmp/cluster-dump
```

| Команда | Зачем |
|---------|-------|
| `version --output=yaml` | Точные версии client/server, platform |
| `cluster-info` | Endpoint API и CoreDNS proxy URL |
| `cluster-info dump` | Полный снимок для support/аудита (осторожно - много данных) |

**Проверка:**

```bash
kubectl version --short 2>/dev/null || kubectl version | head -4
# Client и Server Version: v1.32.x
```

**Откат:** `rm -rf /tmp/cluster-dump` - только удаление дампа.

### Шаг 2 - Nodes и conditions

```bash
kubectl get nodes -o wide
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.conditions[?(@.type=="Ready")].status}{"\n"}{end}'
kubectl describe node k8s-cp-01 | grep -A5 "Conditions:"
kubectl describe node k8s-w-01 | grep -A10 "Conditions:"
```

**Ожидаемый результат:**

```
Conditions:
  Type             Status  Reason                       Message
  ----             ------  ------                       -------
  NetworkUnavailable False   CalicoIsUp                   Calico is running on this node
  MemoryPressure   False   KubeletHasSufficientMemory   ...
  DiskPressure     False   KubeletHasNoDiskPressure     ...
  PIDPressure      False   KubeletHasSufficientPID      ...
  Ready            True    KubeletReady                 kubelet is posting ready status
```

**Проверка:** `Ready=True` на всех nodes; `NetworkUnavailable=False` после Calico.

### Шаг 9 - Функциональный smoke-test

```bash
kubectl create namespace health-check --dry-run=client -o yaml | kubectl apply -f -

kubectl run dns-test -n health-check --image=busybox:1.36 --restart=Never -- \
  nslookup kubernetes.default.svc.cluster.local

kubectl run net-test -n health-check --image=nicolaka/netshoot --restart=Never -- sleep 3600

kubectl wait -n health-check --for=condition=Ready pod/dns-test --timeout=60s
kubectl logs -n health-check dns-test
kubectl exec -n health-check net-test -- ping -c3 $(kubectl get pod -n kube-system -l k8s-app=kube-dns -o jsonpath='{.items[0].status.podIP}')
```

**Ожидаемый результат DNS:**

```
Name:      kubernetes.default.svc.cluster.local
Address 1: 10.96.0.1
```

**Откат smoke-test:**

```bash

```

### Шаг 10 - Сводный скрипт проверки

Сохраните на `k8s-cp-01`:

```bash
cat > /usr/local/bin/k8s-health-check.sh << 'EOF'
#!/bin/bash
set -euo pipefail
export KUBECONFIG=/etc/kubernetes/admin.conf
echo "=== Nodes ==="
kubectl get nodes
echo "=== Non-Running pods ==="
kubectl get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded 2>/dev/null || true
echo "=== API readyz ==="
kubectl get --raw='/readyz' 2>/dev/null || echo "FAIL"
echo "=== Cert expiration ==="
kubeadm certs check-expiration 2>/dev/null | head -15
echo "=== Recent Warnings ==="
kubectl get events -A --field-selector type=Warning 2>/dev/null | tail -5
echo "=== DONE ==="
EOF
chmod +x /usr/local/bin/k8s-health-check.sh
k8s-health-check.sh
```

### Что произошло внутри Kubernetes

```
kubectl get nodes
    ↓
API Server читает Node objects из etcd
    ↓
Kubelet на каждой node периодически обновляет .status.conditions
    ↓
CNI plugin (Calico) выставляет NetworkUnavailable=False

kubectl get pods -n kube-system
    ↓
Static pods (apiserver, etcd, scheduler, CM) управляются kubelet
    ↓
Manifests в /etc/kubernetes/manifests
    ↓
DaemonSets (kube-proxy, calico-node) - через API + controller-manager

curl /readyz
    ↓
API Server internal health aggregator
    ↓
Проверяет: etcd connectivity, informer sync, poststarthook

kubectl logs kube-apiserver-k8s-cp-01
    ↓
API Server → kubelet /container/logs
    ↓
containerd → log file pod sandbox
```

## Troubleshooting

### Node NotReady

```bash
kubectl describe node <name> | grep -A20 Conditions
journalctl -u kubelet -n 50 --no-pager
```

| Причина | Симптом | Fix |
|---------|---------|-----|
| CNI не установлен | `NetworkUnavailable=True` | `kubectl apply -f calico.yaml` |
| containerd down | `PLEG not healthy` | `systemctl restart containerd` |
| Swap on | kubelet refused start | `swapoff -a` |

### CoreDNS не Running

```bash
kubectl describe pod -n kube-system -l k8s-app=kube-dns
kubectl get events -n kube-system | grep coredns
```

Часто: CNI не готов → Pod не получает IP → Pending.

### API /readyz failed

```bash
crictl ps | grep apiserver
ls -la /etc/kubernetes/manifests/
journalctl -u kubelet | grep apiserver
```

Проверить: cert expired, etcd down, port 6443 занят.

### Много Warning Events

```bash
kubectl get events -A --field-selector type=Warning | sort -k1
```

Не все Warning критичны. Фильтруйте по `reason=Failed`, `FailedMount`, `FailedScheduling`.
