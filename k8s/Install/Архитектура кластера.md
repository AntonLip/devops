# Архитектура кластера

## Цель

Разобрать **все компоненты** production-like кластера (Control Plane, worker, etcd, CNI, CSI, Ingress), построить **полную схему взаимодействия** и на **Talos homelab** (read-only) увидеть те же компоненты через `kubectl`, чтобы связать теорию с уже работающим стендом.

---

## Теория

### Control Plane vs Worker Node

| Слой | Где | Компоненты | Задача |
|------|-----|------------|--------|
| **Control Plane** | CP node(s) | API Server, etcd, Scheduler, Controller Manager, CoreDNS (addon), kube-proxy (addon) | State, scheduling, reconciliation |
| **Worker / Data plane** | Worker nodes | kubelet, container runtime, CNI agent, kube-proxy | Запуск Pod, сеть, volumes |
| **Add-ons** | kube-system / отдельные ns | CNI, DNS, metrics, ingress controller | Платформенные сервисы |

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         CONTROL PLANE (k8s-cp-01)                        │
│  ┌─────────────┐  ┌─────────────┐  ┌──────────────┐  ┌────────────────┐ │
│  │ kube-       │  │ kube-       │  │ kube-        │  │ etcd           │ │
│  │ apiserver   │◄─┤ scheduler   │  │ controller-  │  │ (stacked)      │ │
│  │ :6443       │  │             │  │ manager      │  │ :2379          │ │
│  └──────┬──────┘  └──────▲──────┘  └──────▲───────┘  └───────▲────────┘ │
│         │                 │                │                  │          │
│         └─────────────────┴────────────────┴──────────────────┘          │
│                    static Pods (kubelet mirror)                          │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │ HTTPS 6443
          ┌─────────────────────────┼─────────────────────────┐
          ▼                         ▼                         ▼
   ┌─────────────┐           ┌─────────────┐           ┌─────────────┐
   │ WORKER      │           │ WORKER      │           │ (Talos      │
   │ k8s-w-01    │           │ k8s-w-02    │           │  maste1 CP) │
   │ kubelet     │           │ kubelet     │           │             │
```

**kubeadm lab:** stacked etcd на CP. **Talos homelab:** та же модель (1 CP `maste1`), но CNI — **Cilium**, не Calico.

### kube-apiserver

**Зачем:** единственная **официальная** точка входа в state кластера.

**Как работает:**

1. Client (kubectl, kubelet, controller) → TLS + authn.
2. Authorization (RBAC, webhook).
3. Admission (mutating/validating).
4. Read/write **etcd** (единственный компонент CP, пишущий в etcd напрямую).
5. Watch events → подписчики.

```
kubectl apply deployment.yaml
       │
       ▼
  kube-apiserver
       │
       ├──► etcd: Deployment object stored
       │
       └──► watch → Deployment controller → ReplicaSet → Pod spec
                              │
                              ▼
                         scheduler → bind Pod to node
                              │
                              ▼
                         kubelet → start containers
```

**Production:** 3+ API instances за **Load Balancer**; `--advertise-address` и SAN certs должны включать VIP/LB DNS.

---

### etcd

**Зачем:** strongly consistent **key-value store** для всего state Kubernetes.
**Что хранит:** Pod specs, Services, Secrets (base64), RBAC, leases, ConfigMaps.
**Как работает:** Raft consensus; quorum `(N/2)+1` для записи.

| Модель | kubeadm lab | Production HA |
|--------|-------------|---------------|
| **Stacked** | etcd static pod на CP node | 3 CP, etcd на каждом (риск: CP failure = etcd) |
| **External** | не используем | отдельные etcd nodes, LB для apiserver |

**Lifecycle:** при `kubeadm init` генерируются certs в `/etc/kubernetes/pki/etcd/`; kubelet запускает manifest из `/etc/kubernetes/manifests/etcd.yaml`.

**Best practice:** регулярный **snapshot** (глава 15.5.17); disk latency критичен — SSD обязателен.

### kube-scheduler

**Зачем:** выбрать **node** для Pod, у которого ещё нет `spec.nodeName`.
**Не делает:** не запускает контейнеры (это kubelet).
**Фильтры и scores:** ресурсы, taints/tolerations, affinity, topology spread, PVC topology.

```
Pod CREATE (nodeName empty)
       │
       ▼
  scheduler watch
       │
       ├── Filter nodes (NotReady, taints, resources)
       ├── Score nodes (spread, affinity)
       └── Patch Pod spec.nodeName = k8s-w-01
              │
              ▼
         kubelet on k8s-w-01
```

### kube-controller-manager

**Зачем:** набор **control loops**, приводящих фактическое состояние к желаемому.

| Controller (примеры) | Что делает |
|----------------------|------------|
| **Deployment** | RS ↔ Pod replicas |
| **ReplicaSet** | Pod count |
| **Node** | Node Ready/NotReady, evictions |
| **Service** | Endpoints для ClusterIP |
| **EndpointSlice** | modern Endpoints |
| **PV/PVC** | binding, protection |
| **Namespace** | finalizers |
| **TTL** | finished Jobs cleanup |

**Contrast Talos:** на homelab **Cilium operator** — **внешний** controller (LB IPAM), не часть kube-controller-manager

### kubelet (Node Agent)

**Зачем:** агент на **каждой** node; исполняет то, что API Server «решил» для этой node.

**Обязанности:**

- регистрация Node object;
- sync Pod specs (static pods + assigned pods);
- CRI: pull image, start/stop container;
- mount volumes (CSI/node);
- report status, probes;
- **TLS Bootstrap** для worker join.

```
API Server ──watch──► kubelet
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
    CRI (containerd)   CNI plugin    CSI node
         │               │               │
         ▼               ▼               ▼
    Containers       Pod network      Volume mounts
```

**Static pods:** kubelet на CP читает `/etc/kubernetes/manifests/` и запускает API, etcd, scheduler, CM **без** Deployment — «self-hosted» bootstrap.

---

### kube-proxy

**Зачем:** реализовать **Service** abstraction (ClusterIP, NodePort, LoadBalancer на node level).

**Modes:** iptables (default), IPVS, nftables (новее).

```
Client Pod → Service my-svc:80 (ClusterIP 10.96.x.x)
                    │
                    ▼
              kube-proxy rules
                    │
                    ▼
         DNAT to Pod IP:containerPort (backend Endpoints)
```

**На Talos homelab:** kube-proxy DaemonSet в `kube-system` — проверим в практике.

**Contrast Cilium:** Cilium может **replace** kube-proxy (eBPF kube-proxy replacement); у вас Cilium — проверьте `kube-proxy` presence.

---

### CoreDNS

**Зачем:** DNS **внутри** кластера — `my-svc.my-ns.svc.cluster.local`.

**Установка:** kubeadm **addon** после init (Deployment в kube-system).

```
Pod → /etc/resolv.conf → nameserver 10.96.0.10 (kube-dns Service)
                              │
                              ▼
                         CoreDNS pods
                              │
                              ▼
                    forward / cluster.local
```

**Без CoreDNS:** Service discovery по имени **не работает** (только по ClusterIP).

---

### Container Runtime (containerd)

**Зачем:** kubelet не запускает Docker напрямую — только через **CRI**.

**Цепочка (глава 15.5.3):** kubelet → CRI gRPC → containerd → runc → OCI container.

**Sandbox pod:** pause container держит network namespace для Pod.

---

### CNI (Container Network Interface)

**Зачем:** после kubelet создал sandbox, **CNI plugin** настраивает IP, routes, policy.

**Без CNI:** Node может быть Ready, но Pod — **ContainerCreating** / **NetworkPluginNotReady**.

| CNI | kubeadm lab | Talos homelab |
|-----|-------------|---------------|
| **Calico** | да (15.5.9) | — |
| **Cilium** | опционально | **1.18.5**, eBPF, Hubble |
| **Flannel** | простой overlay | — |

```
kubelet CreatePodSandbox
       │
       ▼
  CNI ADD (calico/cilium)
       │
       ├── assign Pod IP from pod CIDR
       ├── setup veth / eBPF
       └── optional NetworkPolicy
```

---

### CSI (Container Storage Interface)

**Зачем:** attach/mount **persistent** volumes (вне in-tree drivers).
**Компоненты:** CSI controller (provision), node plugin (mount).
**kubeadm lab:** CSI не ставим в первых главах; emptyDir/hostPath достаточно до Storage module.

---

### Ingress

**Зачем:** HTTP/HTTPS routing **в кластер** (L7), не путать с Service NodePort.
**Не часть kubeadm:** ставится отдельно (ingress-nginx, Traefik).
**Talos homelab:** `ingress-nginx` namespace — внешний controller + Service type LoadBalancer (IP от Cilium).

```
Internet → LB / NodePort → Ingress Controller → Ingress rules → Service → Pods
```

### Полная схема: создание Pod

```
User: kubectl run nginx --image=nginx
         │
         ▼
    kube-apiserver ──► etcd (Pod object)
         │
         ├──────────────────────────────────────┐
         ▼                                      ▼
   kube-scheduler                        (watch)
   assign nodeName                              │
         │                                      ▼
         └──────────────► kubelet (target node)
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
              CRI sandbox   CNI ADD    mount volumes
                    │           │           │
                    └───────────┴───────────┘
                                ▼
                         Pod Running
                                │
                    kube-proxy ◄─┘ (if Service exists)
                    CoreDNS (name resolution)
```

### Production best practices

| Область | Рекомендация |
|---------|--------------|
| CP | dedicated nodes, taints, no user workloads |
| etcd | SSD, snapshot, odd number for HA |
| kubelet | `--config` sync, resource reservations |
| CNI | выбор под policy (Calico/Cilium NP) |
| Addons | pin versions, GitOps manifests |
| Observability | metrics-server, logs, audit (Talos: Hubble) |

**Типичные ошибки:**

- думать, что scheduler «запускает» Pod;
- путать **Service** (kube-proxy) и **Ingress** (L7);
- забыть CNI → все Pod Pending;
- искать «docker» на node — нужен **containerd + CRI**.

```
Вы: kubectl get pods -n kube-system
         │
         ▼
    kube-apiserver (auth: ваш admin cert / OIDC)
         │
         ▼
    etcd → возвращает Pod objects
         │
         ▼
    kubectl render table

Static pods на CP (Talos/kubeadm):
         │
         ▼
    kubelet mirror pod ← manifest на disk
         │
         ▼
    status.podIP, conditions → API → вы видите Running

DaemonSet (Cilium, kube-proxy):
         │
         ▼
    DS controller → Pod per matching node
         │
         ▼
    kubelet запускает на каждой node
```
