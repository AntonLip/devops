
# Docker - volumes (теория и практика)

Данные в контейнере по умолчанию живут в **writable layer** поверх read-only слоёв образа: при удалении контейнера они **пропадают**. Чтобы персистентность, обмен с хостом и предсказуемая производительность совпадали с ожиданиями DevOps, Docker вводит **тома (volumes)** и **bind mount** - оба реализованы через **mount namespace** Linux (см. [11.1.1](../11.1%20Docker%20begin/11.1.1%20Docker%20-%20Linux%2C%20namespaces%20и%20контейнер%20без%20Docker.md)): внутри контейнера путь монтирования «перекрывает» слой образа, а источник данных либо на хосте по явному пути, либо в управляемом Docker хранилище.

Официально: [Use volumes](https://docs.docker.com/storage/volumes/), [Bind mounts](https://docs.docker.com/storage/bind-mounts/), [tmpfs mounts](https://docs.docker.com/storage/tmpfs/).

---

## 1. Три способа дать контейнеру «место для данных»

| Механизм         | Где физически данные                                                    | Кто управляет жизненным циклом                 | Типичное применение                                                                                               |
| ---------------- | ----------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Bind mount**   | Указанный **каталог или файл на хосте**                                 | Вы (права, бэкапы, квоты - вне Docker)         | Разработка (код с хоста в контейнере), конфиги, интеграция с уже существующим каталогом данных                    |
| **Named volume** | Каталог в области Docker (часто `/var/lib/docker/volumes/...` на Linux) | **`docker volume`**                            | Персистентные данные БД, артефакты, всё, что должно пережить пересоздание контейнера без привязки к пути на хосте |
| **tmpfs mount**  | **RAM** (tmpfs), не на диск                                             | Ядро; данные исчезают при остановке контейнера | Чувствительные кэши, сокеты, временные секреты в памяти                                                           |

**Анонимный volume** - это именованный том без явного имени: Docker сам создаёт длинный ID; удобно в Dockerfile (`VOLUME /data`), чтобы слой образа не «раздувался» записью, но для эксплуатации предпочтительно **именовать** тома осмысленно.

## 2. Bind mount: как это связано с Linux

При bind mount ядро монтирует **уже существующий** inode дерева хоста в точку монтирования в **mount namespace** контейнера. Процесс в контейнере видит те же байты, что и процесс на хосте по исходному пути (с учётом кэша страниц).

Следствия:

- **Права и владелец (UID/GID)** проверяются по числовым идентификаторам. Если в контейнере процесс с UID 1000, а на хосте каталог принадлежит root `700`, запись **не получится**, пока вы не поправите права или не запустите контейнер с подходящим пользователем (`--user`, user в образе).
- **Симлинки и абсолютные пути** на хосте ведут себя так, как ожидает ядро; не монтируйте вслепую `/` или сокеты без понимания последствий.
- **Секреты:** файл `.env` или каталог `~/.ssh` с bind mount **виден** контейнеру в открытом виде; это не замена Vault/secret manager.

## 3. Named volume: плюсы для эксплуатации

- Путь на хосте **абстрагирован**: при переносе на другой сервер с тем же Docker вы подключаете том по **имени** в compose/stack.
- Docker может использовать **драйвер** тома (по умолчанию `local`; в облаках - плагины к NFS, CSI и т.д.).
- Удобно **бэкапить** каталог тома на диске или снимок на уровне СХД, если политика это допускает.

### 3.1. Драйверы томов (`volume driver`): какие бывают и как использовать

**Драйвер тома** - это плагин или встроенный код, который решает: **где и как** хранятся данные тома, как создаётся/удаляется том и какие **`-o` / `--opt`** он понимает. У каждого драйвера свой набор опций; общая схема для вас как для DevOps: **`docker volume create -d имя_драйвера`** и при необходимости **`-o ключ=значение`**.

#### Встроенный драйвер `local` (по умолчанию)

- Данные лежат на диске узла в области Docker (типичный путь на Linux: под **`/var/lib/docker/volumes/`**).
- На **Linux** драйвер `local` умеет монтировать не только «обычный каталог», но и спец. случаи через **`-o`**, в духе опций **`mount(8)`**: например **tmpfs** на диске как «том», **NFS**, **btrfs**-устройство и т.д. (см. [документацию `volume create`](https://docs.docker.com/reference/cli/docker/volume/create/) и примеры в разделе 5).
- На **Windows** у `local` отдельные правила; опции `-o` для «unix-style» монтирования там не применимы.

Создание явно с `local` (обычно не нужно - это умолчание):

```bash
docker volume create -d local mydata
```

#### Плагины томов (сторонние драйверы)

Docker поддерживает **плагины** ([volume plugins](https://docs.docker.com/engine/extend/legacy_plugins/#volume-plugins), современнее - интеграции через **managed plugins** `docker plugin install` или CSI в Kubernetes, где Docker Engine уже не центр). Примеры **идей** драйверов (конкретные имена зависят от вендора и года выпуска плагина):

| Класс                      | Зачем                                                             |
| -------------------------- | ----------------------------------------------------------------- |
| **Сетевые ФС (NFS, CIFS)** | Общий том между несколькими хостами Docker без SAN на каждом узле |
| **Облачные диски**         | Том как EBS/GCE Persistent Disk через драйвер провайдера          |
| **СХД / SDS**              | Portworx, NetApp Trident (в K8s чаще), и т.п.                     |

Как **подключить** плагин: следовать инструкции вендора (`docker plugin install ...` или установка пакета, который регистрирует драйвер в демоне). Проверка, что демон видит драйвер:

```bash
docker info
# смотрите секцию Plugins / Volume
```

Создание тома с **не-local** драйвером (имя драйвера и **`-o`** - строго из документации плагина; ниже вымышленный пример формы команды):

```bash
docker volume create -d vendor/myvolume --label purpose=demo -o size=10G vol-from-plugin
```

Подключение к контейнеру **после** создания тома - как у обычного named volume: **`-v vol-from-plugin:/data`** или **`--mount type=volume,source=vol-from-plugin,target=/data`**. Отдельный ключ **`volume-driver=`** в **`docker run --mount`** имеет смысл, когда том создаётся «на лету» вместе с запуском контейнера; синтаксис зависит от версии Docker - сверяйтесь с **`docker run --help`** и [документацией по `--mount`](https://docs.docker.com/engine/storage/volumes/).

#### Как выбрать драйвер на практике

- **Один хост, персистентность на диске узла** - **`local`** без плагинов.
- **Несколько хостов, общие файлы** - сетевой том (**NFS/CIFS** или корпоративный плагин); следите за **кворами записи** и семантикой блокировок (БД на NFS - отдельная инженерная дискуссия).
- **Kubernetes** - как правило **CSI** и **StorageClass**, а не ручные Docker volume plugins на нодах; модуль 11.2 задаёт базу для понимания, «что такое том» на уровне Engine.

Официальный обзор: [Volume drivers](https://docs.docker.com/storage/volumes/#use-a-volume-driver).

## 4. Синтаксис: `-v` и рекомендуемый `--mount`

Старый стиль (короче, но легче ошибиться в порядке полей):

```bash
docker run -v имя_или_путь_хоста:путь_в_контейнере[:ro]
```

Явный стиль ([`--mount`](https://docs.docker.com/storage/bind-mounts/#start-a-container-with-a-bind-mount)):

```bash
docker run --mount type=bind,source=/path/on/host,target=/app,readonly
docker run --mount type=volume,source=mydata,target=/var/lib/postgresql/data
docker run --mount type=tmpfs,target=/run/secrets,tmpfs-size=16m
```

Поля **`source`/`target`**, **`readonly`**, для tmpfs - **`tmpfs-size`**, **`tmpfs-mode`**. Подробный разбор всех опций - в разделе 5 ниже.

## 5. Справочник параметров команд (тома и монтирование)

Краткая навигация по подкомандам:

| Команда | Назначение |
|---------|------------|
| `docker volume create` | Создать том (имя - последний аргумент или случайное) |
| `docker volume ls` | Список томов |
| `docker volume inspect` | JSON по одному или нескольким томам |
| `docker volume rm` | Удалить один или несколько томов |
| `docker volume prune` | Удалить **неиспользуемые** тома пакетно |
| `docker run/create` + `-v` / `--mount` / `--tmpfs` | Подключить том/bind/tmpfs к контейнеру |

Актуальный полный список флагов всегда смотрите в **`docker <команда> --help`** на своей версии Docker.

### 5.1. `docker volume create [OPTIONS] [VOLUME]`

Если **`[VOLUME]`** не указан, Docker генерирует **случайное имя**.

| Параметр                 | Краткая форма | Смысл                                                                                                                                                                                                                                      |
| ------------------------ | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`-d`**, **`--driver`** | `-d`          | Имя драйвера тома. По умолчанию **`local`**. Другие значения - плагины (NFS, cloud и т.д.).                                                                                                                                                |
| **`--label`**            | -             | Метка `key=value`; флаг можно повторять несколько раз.                                                                                                                                                                                     |
| **`-o`**, **`--opt`**    | `-o`          | Опция драйвера в виде `ключ=значение`; передаётся драйверу как есть. Для встроенного **`local`** на Linux допустимы опции в духе `mount` (например NFS: `type=nfs`, `o=addr=...`, `device=:/export/path`). На Windows у `local` опций нет. |
| **`-h`**, **`--help`**   | -             | Справка по подкоманде.                                                                                                                                                                                                                     |
|                          |               |                                                                                                                                                                                                                                            |

Дополнительные флаги для **Swarm cluster volumes** (API 1.42+, не все установки): **`--availability`**, **`--group`**, **`--limit-bytes`**, **`--required-bytes`**, **`--scope`**, **`--secret`**, **`--sharing`**, **`--topology-preferred`**, **`--topology-required`**, **`--type`** - см. [документацию `volume create`](https://docs.docker.com/reference/cli/docker/volume/create/); в учебном сценарии на одном хосте обычно достаточно **`-d`** и **`-o`**.

Примеры:

```bash
docker volume create --label project=demo --label env=lab myvol
docker volume create -d local -o type=tmpfs -o device=tmpfs -o o=size=100m,uid=1000 ramvol
```

### 5.2. `docker volume ls [OPTIONS]`

| Параметр                 | Смысл                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| **`-f`**, **`--filter`** | Фильтр: например `dangling=true` (тома без ссылки на контейнер), `name=prefix*`, `label=key=value`, `driver=local`. |
| **`--format`**           | Шаблон Go для вывода строк вместо таблицы (как у `docker ps --format`).                                             |
| **`-q`**, **`--quiet`**  | Только **имена** томов, по одному в строке.                                                                         |

### 5.3. `docker volume inspect [OPTIONS] VOLUME [VOLUME...]`

| Параметр | Смысл |
|----------|--------|
| **`-f`**, **`--format`** | Шаблон Go по **каждому** тому (например `'{{ .Mountpoint }}'`). |

Вывод - **массив JSON** (даже для одного имени). Несколько имён подряд - один JSON-массив из нескольких объектов.

### 5.4. `docker volume rm [OPTIONS] VOLUME [VOLUME...]`

У подкоманды обычно **нет** расширенных флагов (кроме **`--help`**): перечисляете одно или несколько **имён** томов. Том, к которому подключён **работающий** контейнер, удалить нельзя - сначала остановите/удалите контейнер или отмонтируйте том.

### 5.5. `docker volume prune [OPTIONS]`

| Параметр | Смысл |
|----------|--------|
| **`-a`**, **`--all`** | Удалить **все** неиспользуемые тома, в том числе **именованные**, у которых нет ссылок (без этого режима часто удаляются в основном **анонимные** неиспользуемые - уточняйте по `--help` версии). |
| **`--filter`** | Ограничить кандидатов на удаление (например по `label`). |
| **`-f`**, **`--force`** | Не спрашивать подтверждение в интерактивном режиме. |

Опасная операция на shared-хостах: перед запуском **`docker volume ls`** и резервные копии.

### 5.6. `docker run` / `docker create`: `-v` и `--volume`

Синтаксис одного монтирования:

```text
-v|--volume [ИСТОЧНИК_НА_ХОСТЕ:]ТОЧКА_В_КОНТЕЙНЕРЕ[:РЕЖИМ]
```

- **`ИСТОЧНИК`** опущен - создаётся **анонимный** том в каталоге Docker.  
- **`ИСТОЧНИК`** - абсолютный путь на хосте - **bind mount**.  
- **`ИСТОЧНИК`** - имя без `/` в начале - обычно **named volume** (если том не существует, named volume часто создаётся автоматически при запуске - поведение зависит от настроек; явное `docker volume create` предпочтительнее).

**`РЕЖИМ`** (через двоеточие третьим полем; можно комбинировать через запятую, зависит от ОС и версии):

| Значение                                        | Смысл                                                                                                           |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **`rw`** / **`ro`**                             | Чтение-запись (по умолчанию) / только чтение (для bind и volume).                                               |
| **`z`** / **`Z`**                               | Перелабелить контекст SELinux для общего (`z`) или приватного (`Z`) тома (в основном RHEL/CentOS/Fedora).       |
| **`consistent`**, **`cached`**, **`delegated`** | Когерентность кэша для bind mount на **Docker Desktop** (macOS/Windows); на чистом Linux обычно не применяются. |
| **`nocopy`**                                    | Для volume: не копировать заранее данные из образа в том при первом монтировании (редкие сценарии).             |
| **`bind-propagation=...`**                      | Редко в старом `-v`; для тонкой настройки чаще используют **`--mount`**.                                        |

Флаг **`-v`** можно указывать **несколько раз** для нескольких монтирований.

### 5.7. `docker run` / `docker create`: `--mount`

Один блок монтирования:

```text
--mount type=<тип>,ключ=значение,ключ=значение,...
```

Общие ключи (где применимо):

| Ключ                                         | Альтернатива | Смысл                                                                                                                                        |
| -------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **`type`**                                   | -            | **`bind`** \| **`volume`** \| **`tmpfs`**.                                                                                                   |
| **`source`** / **`src`**                     | -            | Для **bind** - путь на хосте; для **volume** - имя тома. Для анонимного volume можно опустить или оставить пустым (см. документацию версии). |
| **`destination`** / **`dst`** / **`target`** | -            | Путь **внутри контейнера** (обязателен).                                                                                                     |
| **`readonly`** / **`ro`**                    | -            | Только чтение.                                                                                                                               |

Дополнительно для **`type=volume`**:

| Ключ | Смысл |
|------|--------|
| **`volume-driver`** | Драйвер тома (если не `local`). |
| **`volume-label`** | Метка на создаваемом томе. |
| **`volume-nocopy`** | Аналог флага `nocopy` у `-v`. |
| **`volume-opt`** | Пара `ключ=значение` для драйвера тома. |

Для **`type=bind`**:

| Ключ | Смысл |
|------|--------|
| **`bind-propagation`** | `shared`, `slave`, `private`, `rshared`, `rslave`, `rprivate` - распространение mount-событий (ядро Linux). |

Для **`type=tmpfs`**:

| Ключ | Смысл |
|------|--------|
| **`tmpfs-size`** | Размер tmpfs (например `16m`, `100m`). |
| **`tmpfs-mode`** | Права в восьмеричном виде, например `1770`. |
| **`tmpfs-options`** | Сырой список опций tmpfs (зависит от версии; при сомнении см. `--help`). |

### 5.8. `docker run`: отдельный флаг `--tmpfs`

Короткая форма tmpfs **без** именованного тома:

```text
--tmpfs ПУТЬ[:опции]
```

**`опции`** - список в стиле монтирования tmpfs (`rw`, `size=64m`, `uid=1000` и т.д., через запятую). Отличие от **`--mount type=tmpfs`**: в основном синтаксис и удобство; семантика одна - файловая система в RAM.

### 5.9. Разбор JSON: пример `docker volume inspect demo-data`

Команда **`docker volume inspect имя`** возвращает **массив JSON** из одного объекта (так же устроены `docker inspect` для контейнеров и образов - единый формат CLI).

Пример вывода для тома `demo-data`:

```json
[
  {
    "CreatedAt": "2026-04-14T21:22:51+03:00",
    "Driver": "local",
    "Labels": null,
    "Mountpoint": "/var/lib/docker/volumes/demo-data/_data",
    "Name": "demo-data",
    "Options": null,
    "Scope": "local"
  }
]
```

| Поле | В примере выше | Смысл |
|------|----------------|--------|
| **CreatedAt** | `2026-04-14T21:22:51+03:00` | Время создания тома (ISO 8601; `+03:00` - смещение от UTC). |
| **Driver** | `local` | Драйвер хранения. **`local`** - данные на диске узла в каталоге под управлением Docker. Другие драйверы (NFS, CSI-плагины и т.д.) меняют поведение и набор **Options**. |
| **Labels** | `null` | Метки key/value (как у контейнеров). `null` - меток нет; иначе фильтрация `docker volume ls --filter label=...`. |
| **Mountpoint** | `/var/lib/docker/volumes/demo-data/_data` | **Реальный каталог на хосте** с файлами тома. Сюда попадает монтирование при `-v demo-data:/путь/в/контейнере`. На rootless или кастомном `data-root` путь будет другим. |
| **Name** | `demo-data` | Имя тома в CLI и в `source=` для `--mount`. |
| **Options** | `null` | Параметры драйвера (см. `docker volume create --help`). Для `local` без доп. опций часто `null`. |
| **Scope** | `local` | Том привязан к **данному** Docker Engine (хосту). В других сценариях встречаются иные значения в зависимости от версии и оркестрации. |

Полезно в скриптах:

```bash
docker volume inspect -f '{{ .Mountpoint }}' demo-data
```

## 6. Практика A - именованный том под «данные сервиса»

```bash
docker volume create demo-data
docker run -d --name dbdemo -e POSTGRES_PASSWORD=demo \
  -v demo-data:/var/lib/postgresql/data \
  postgres:16-alpine
docker volume inspect demo-data
docker exec -it dbdemo psql -U postgres -c "SELECT 1;"
docker stop dbdemo
docker rm dbdemo
docker run -d --name dbdemo2 -e POSTGRES_PASSWORD=demo \
  -v demo-data:/var/lib/postgresql/data \
  postgres:16-alpine
```

Идея: после `rm` контейнера **данные остались** в `demo-data`. Очистка учебного стенда:

```bash
docker stop dbdemo2 && docker rm dbdemo2
docker volume rm demo-data
```

## 7. Практика B - bind mount для разработки

```bash
mkdir -p /tmp/devapp && echo "console.log('hi')" > /tmp/devapp/app.js
docker run --rm -it -v /tmp/devapp:/app -w /app node:20-alpine sh -c 'node app.js && ls -la'
```

Код на хосте сразу виден в контейнере; смена файла на хосте отражается без пересборки образа.

## 8. Практика C - tmpfs для временного каталога в RAM

```bash
docker run --rm --mount type=tmpfs,target=/cache,tmpfs-size=32m \
  alpine df -h /cache
```

Полезно, когда не хотите оставлять след на диске или нужен быстрый каталог под lock-файлы.

## 9. Риски и заметки для продакшена

- Не путать **удаление контейнера** с **удалением тома**: `docker rm -v` удалит и **анонимные** тома, привязанные к контейнеру; именованный том без `docker volume rm` останется.
- **Один том - один смысл** (одна БД или один сервис), иначе сложно мигрировать и бэкапить.
- **SELinux/AppArmor** на хосте (RHEL и др.): для bind mount иногда нужны флаги `:z`/`:Z` или настройка контекста - это уже политика безопасности хоста, не «универсальная команда».
- Документация по драйверам и плагинам: [Volume drivers](https://docs.docker.com/storage/volumes/#use-a-volume-driver).
