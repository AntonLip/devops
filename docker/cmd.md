
# Docker - базовые команды и практика

Ниже - минимальный набор команд для ежедневной работы и короткий чеклист практики. Установка зависит от ОС: ориентируйтесь на [официальную документацию Docker Engine](https://docs.docker.com/engine/install/) (репозитории пакетов, post-install шаги для группы `docker`).

После установки проверьте:

```bash
docker version
docker info
```

---

## 1. Запуск и жизненный цикл контейнера

| Команда | Назначение |
|---------|------------|
| `docker run [опции] образ [команда]` | Создать и запустить контейнер из образа |
| `docker ps` | Список **работающих** контейнеров |
| `docker ps -a` | Все контейнеры, включая остановленные |
| `docker logs [-f] контейнер` | Логи stdout/stderr (`-f` - follow) |
| `docker exec -it контейнер sh` | Интерактивная оболочка **внутри** работающего контейнера |
| `docker stop контейнер` | Корректная остановка (SIGTERM, затем SIGKILL) |
| `docker rm контейнер` | Удалить **остановленный** контейнер |
| `docker rm -f контейнер` | Принудительно остановить и удалить |

Частые флаги `docker run`:

- `-d` - detached (в фоне).
- `--name имя` - имя вместо случайного.
- `-p хост:контейнер` - публикация порта (например `-p 8080:80`).
- `-v /путь/на/хосте:/путь/в/контейнере` - bind mount.
- `--rm` - удалить контейнер после остановки (удобно для одноразовых задач).

Пример:

```bash
docker run -d --name web -p 8080:80 nginx:alpine
docker logs -f web
docker exec -it web sh
docker stop web
docker rm web
```

### 1.1. Detached-запуск и как зайти в уже работающий контейнер

**Detached** (`-d`) означает: контейнер стартует **в фоне**, терминал сразу возвращается к приглашению shell на хосте; основной процесс контейнера (например `nginx`, `sleep`) продолжает работать.

**Последовательность:**

1. Запустить контейнер отсоединённо и дать имя (или потом искать по ID):

```bash
docker run -d --name mybox alpine:3.19 sleep 3600
```

2. Убедиться, что он **running**, и при необходимости узнать имя или ID:

```bash
docker ps
```

3. **Зайти внутрь** работающего контейнера - открыть интерактивную оболочку (новый процесс в тех же namespace’ах):

```bash
docker exec -it mybox sh
```

Внутри можно выполнять `ps`, `hostname`, `ls` и т.д. Выход из оболочки - `exit` (контейнер при этом **не** останавливается, останавливается только сессия `exec`).

4. Если контейнер создавался **без** `--name`, в `docker ps` смотрите столбец **CONTAINER ID** и подставляйте короткий или полный ID вместо `mybox`:

```bash
docker exec -it <CONTAINER_ID> sh
```

**`docker attach`** - другое действие: подключиться **к stdin/stdout основного процесса** контейнера (к тому, что запускал `docker run`). Для интерактивной оболочки в уже работающем контейнере в учебных сценариях чаще используют именно **`docker exec -it`**. Отключиться от `attach` без остановки контейнера: обычно **`Ctrl+P`, затем `Ctrl+Q`** (sequence detach); выход по **`Ctrl+C`** или **`Ctrl+D`** может завершить основной процесс - смотрите документацию по вашей версии Docker и типу процесса.

## 2. Образы: загрузка, список, удаление

| Команда | Назначение |
|---------|------------|
| `docker pull образ:тег` | Скачать образ из registry (по умолчанию Docker Hub) |
| `docker images` | Список локальных образов |
| `docker rmi образ` | Удалить образ (контейнеры на его основе должны быть удалены или пересозданы) |
| `docker inspect образ\|контейнер` | JSON с метаданными (сеть, env, монтирования…) |

Тег **`latest`** не гарантирует «самую свежую» семантику в проде - лучше явные версии (`nginx:1.25-alpine`).

## 3. Сборка из Dockerfile

| Команда | Назначение |
|---------|------------|
| `docker build -t имя:тег .` | Сборка из `Dockerfile` в текущем каталоге |
| `docker build -f путь/Dockerfile .` | Другой файл рецепта |

В корне проекта держите **`.dockerignore`** (по аналогии с `.gitignore`), чтобы не слать в контекст сборки артефакты сборки, `.git`, большие данные.

Минимальный пример `Dockerfile`:

```dockerfile
FROM alpine:3.19
RUN apk add --no-cache curl
CMD ["sleep", "infinity"]
```

```bash
docker build -t mydemo:1.0 .
docker run --rm -it mydemo:1.0 sh
```

## 4. Мини-практика (чеклист)

Выполните по порядку и убедитесь, что понимаете каждый шаг:

1. `docker pull alpine:3.19` (или другой небольшой образ).
2. `docker run -it --name test alpine:3.19 sh` - выйти из shell (`exit`).
3. `docker ps -a` - увидеть остановленный `test`.
4. `docker start -ai test` - снова зайти, выйти.
5. `docker rm test`.
6. `docker run -d --name sleeper alpine:3.19 sleep 300`.
7. `docker exec -it sleeper sh`, внутри - `hostname`, `ps`.
8. `docker inspect sleeper` - найти секции `NetworkSettings`, `Mounts`.
9. `docker stop sleeper && docker rm sleeper`.
10. `docker rmi alpine:3.19` (если образ больше не нужен).
